書籍「育てて学ぶ はじめての自作プログラミング言語」の原稿について、以下の観点とルールを守り批判的に確認・フィードバックを行ってください。指示がない限り修正はせず、指摘のみ行ってください。

## 1. 基本・編集方針
- **正確性と品質**: 技術的誤り、誤字脱字、表記ゆれがないこと。初出用語には簡潔な説明をつける。
- **句読点**: 文末に付加的に「（負け惜しみ」のような一言を付け加える場合はカッコを閉じない。
- **導入とまとめ・ヒキ**: 
  - 導入は読者のモチベーションを高める方向づけを行う。
  - 節末尾には重要ポイントのまとめと、次回への興味を惹きつける「ヒキ（予告文）」を必ず入れる（ない場合は追加を提案）。
- **コード・差分の完全性**:
  - 提示コードが想定通り動作すること。
  - 実装コード（`toil.py` 等）の差分と原稿の `diff` を突合し、クラス・関数内だけでなくモジュールレベルの型定義エイリアス（`type Expr`, `type Value` 等）も含めて差分の反映漏れがないか確認すること。
  - `diff` 内のクラス名・関数名やインデントが実際のコード構造と矛盾していないこと。
- **ターゲット層**: 「Python の基礎は知っているが言語処理系は初めて」の読者向けに、厳密さより楽しさ・スモールステップを優先。親しみやすいトーンを維持する。

## 2. タイポグラフィと書式ルール
※バッククォート等の書式を判定する際は、目視だけでなく必ず生のテキスト（`view_file` や `grep` 等）で一文字ずつ確認すること。

- **インラインコード（バッククォート）**:
  - キーワード、型、変数名、AST タグ、関数名（原則 `func()` 形式）はバッククォートで囲む。識別子はダブルクォートで囲まない（例: `add`）。
  - 解説対象のコード中に登場する具体的な数値（例: `2` や `3`）もバッククォートで囲む。
- **通常テキスト**:
  - 構文の概念そのもの（例: if 文、while 式）や単独の数値（例: 1、100）は通常テキスト。
- **数式**: 数学・アルゴリズム上の抽象的な変数は数式（`$n$` 等）で書く。
- **差分**: コードの変更点は `diff` 形式で示す（実行例を除く）。

## 3. 用語・表記ルール
- **属性**: `self.name = name` のような代入で定義されるものは「属性（attribute）」と呼ぶ（「プロパティ」と混同しない）。
- **配列**: Python のリスト（`list`）についても、Toil の概念と統一するため原則「配列」と表記する。
- **要素の数え方**: リストやタプルの要素位置は、「2 つめ」「3 つめ」「4 つめ」および「1 つ」のように「算用数字＋ひらがな」で統一する（「二つ目」「ふたつめ」等の混在を避ける）。

## 4. 章・節構成
- **タイトル表記**:
  - 章タイトル（見出し・リスト等）は全角スペース区切り（例: `第 4 章　基本のインタプリタ`）。※textlint 回避のため。
  - 節タイトル（フロントマター等）は半角スペース区切り（例: `title: "4.11 配列"`）。
- **章の機能リスト**: 章冒頭の追加機能リストが実際の節の順番と完全に一致しているか確認する。
- **リンク**: ソースおよび差分リンクが `https://github.com/koba925/toil-book` 上の正しい形式・ブランチ名になっているか確認する。

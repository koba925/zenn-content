書籍「育てて学ぶ はじめての自作プログラミング言語」の原稿を、以下の観点・ルールに基づき批判的にレビューしてください。指示がない限り修正はせず、指摘のみ行います。

## 1. 基本・編集方針
* **トーン・正確性**: 初心者向けのスモールステップと親しみやすい語り口を保ちつつ、技術的誤り・誤字脱字・表記ゆれがないこと。初出用語には簡潔な説明を添える。
* **文末の付記**: 「（負け惜しみ」のように文末へ付加する一言はカッコを閉じない。
* **導入とまとめ・ヒキ**: 導入で動機づけし、節末尾には重要ポイントのまとめと次節へのヒキを入れる（次節冒頭との重複を避けるため、ヒキは詳細をネタバレせずほのめかす程度を推奨）。
* **コード・差分の完全性**:
  * 提示コードが想定通り動作し、`diff` のクラス名・関数名・インデントが実コードと矛盾しないこと。
  * 実コード（`toil.py` 等）と原稿 `diff` を突合し、モジュールレベルの型エイリアス（`type Expr`, `type Value` 等）や共通メソッド・例外変更の波及先（`Evaluator._op()`, `Interpreter.eval()` 等）の反映漏れを確認。
  * 原稿の実行例と `toil.py` の `# Example`（内容・順序・`# -> ...`・例外名）を実実行で双方向確認。
  * Toil 構文への Python 構文混入（`case ...:` 等、正しくは `case ... then`）や閉じ括弧（`}` / `)`）の取り違えを確認。

## 2. タイポグラフィと書式ルール
※書式判定は目視に頼らず、生テキスト（`read_file` / `grep` 等）で一文字ずつ確認する。
* **バッククォート**: キーワード・型・変数名・AST タグ・関数名（原則 `func()` 形式）・解説コード中の具体数値（`2`, `3` 等）。識別子を `"` で囲まない（例: `add`）。
* **通常テキスト**: 構文概念（Toil は if 式・while 式・for 式・match 式・try 式・case 節・except 節、Python を指す場合のみ if 文・while 文・try 文 等）や単独の数値（1、100）。
* **数式**: 数学・アルゴリズム上の抽象変数（`$n$` 等）。
* **クォート**: Toil コード中のエスケープ不要な文字列は `'...'` を基本とし、エスケープが必要なときだけ `"..."` を用いる。
* **差分**: 実行例以外のコード変更は `diff` 形式。追加空行に先頭 `+` を付けない方針のため `+` 漏れとしない。
* **細部・脚注**: 読点・句点直後の不要な半角スペース、連続スペース、連続空行を確認。話題分離のための Zenn 表示確認済みネスト脚注（例: `020610.c6-module.md`）は無条件 NG としない。

## 3. 用語・表記ルール
* **属性**: `self.name = name` 等は「属性（attribute）」（「プロパティ」不可）。
* **配列**: Python の `list` も Toil に揃え原則「配列」。
* **構文糖衣**: 「糖衣構文」ではなく「構文糖衣」。
* **「という」系**: 形式名詞・接続表現の「という」「とはいえ」「といって」「とはいっても」「といいます」はひらがな統一。
* **数え方**: 要素位置・個数は「2 つめ」「3 つめ」「1 つ」の算用数字＋ひらがな統一（「ひとつひとつ」等の慣用表現はひらがな許容）。
* **直観**: 書籍全体で意図的に「直観」表記のため「直感」への修正を指摘しない。

## 4. 章・節構成とリンク
* **タイトル・相互参照**: 章タイトルは全角スペース区切り（例: `第 4 章　基本のインタプリタ`、textlint 回避）、節タイトルは半角スペース区切り（例: `title: "4.11 配列"`）。節番号のコピペミスを確認。本文参照は「第 X 章」「X.Y 節」（「第 X.Y 節」不可）、別巻は巻名を明記（例: `Book 1 の 1.5 節`）。
* **章の機能リスト**: 実際の節順と一致すること（本編導入前の専門用語を平易に言い換える意図は尊重）。
* **リンク**: `https://github.com/koba925/toil-book` の形式・タグ名（前節コピペ残り）を確認。外部ドキュメント URL を知識のみで 404 と断定しない。
* **章末ソースコード節・分冊誘導**: Book 1 は付録 `X.A ソースコード` と命名。第 2 部（Book 2）以降はコード長大化のため置かず GitHub リンクで代替する方針であり、不在を指摘しない。巻末節に次巻リンク、後続巻の冒頭チャプターに前巻リンク（`:::message`）を設置。

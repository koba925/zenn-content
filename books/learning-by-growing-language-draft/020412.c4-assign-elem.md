---
title: "4.12 配列要素への代入"
---

配列はタプルと何が一番違うかというと、配列は要素への代入ができるということです。`arr[2] = 3` みたいに書くやつですね。ただしこれは Python では、という話で、配列要素への代入ができない言語もタプルの要素に代入できる言語もあります。Toil では Python の仕様を採用します。

文法は `arr[2] = 3` のように書くこととします。すでにその要素は定義済みで存在していて、それを書き換える操作なので `:=`(`define`) ではなく `=`(`assign`) です。

今まで `=` の左辺には変数が来ると思っていましたが、今回はそうではありません。`(assign, [(index, [arr, 2]), 3])` のように、左辺に `(index, [arr, 2])` のような形が現れます。右辺に `arr[2]` のような式が現れた時と同じ形です。

```py
    # Example

    print("Assign to an array element:")

    print(toil.ast(r""" arr[2] = 3 """)) # -> (assign, [(index, [arr, 2]), 3])
```

ところで、まだなにも修正していないのにエラーになりませんね？構文解析では以下のように左辺も右辺も `_and_or()` で処理していて、特にチェックもしていないので右辺だろうが左辺だろうが気にせずに `(index, [arr, 2])` のような AST を返すのです。

```py
class Parser:
    ...

    def _define_assign(self):
        return self._binary_right({
            Ident(":="): Ident("define"), Ident("="): Ident("assign")
        }, self._and_or)

    ...

    def _binary_right(self, ops, sub_elem):
        left = sub_elem()
        if type(op := self._current_token()) is Ident and op in ops:
            self._current_and_advance()
            return (ops[op], [left, self._binary_right(ops, sub_elem)])
        else:
            return left

```

ていねいにやるなら、`_define_assign()` で左辺がどういう形をしているか確認して、想定外の形だったらエラーにすればよいわけですが、そのままでも `walk()` するとエラーになることもあってチェックは行っていません[^strange-error]。

[^strange-error]: `assign` がないよ、というエラーになってちょっと驚くかもしれませんが、現時点では `eval()` が `(assign, [(index, [arr, 2]), 3])` という AST を受け取ると、知らない形なので `assign` という関数を呼ぶんだな、と思ってしまうためです。

```py
    print(toil.walk(r""" arr[2] = 3 """)) # -> Undefined variable
```

ということで今回の修正点は `Evaluator` クラスになります。


```diff py
 class Evaluator:
     def eval(self, expr: Expr, env: Environment) -> Value:
         match expr:
             ...
             case (Ident("define"), [Ident() as ident, expr]):
                 return env.define(ident, self.eval(expr, env))
-            case (Ident("assign"), [Ident() as ident, expr]):
-                return env.assign(ident, self.eval(expr, env))
+            case (Ident("assign"), [left_expr, right_expr]):
+                return self._assign(left_expr, right_expr, env)
             case (Ident("seq"), exprs): return self._seq(exprs, env)
             ...
 
+    def _assign(self, left_expr, right_expr, env):
+        val = self.eval(right_expr, env)
+        match left_expr:
+            case Ident() as ident:
+                return env.assign(ident, val)
+            case (Ident("index"), [coll_expr, index_expr]):
+                coll_val = self.eval(coll_expr, env)
+                index_val = self.eval(index_expr, env)
+                assert isinstance(coll_val, list) and isinstance(index_val, int), \
+                    f"Invalid index assignment @ _assign(): {left_expr}"
+                coll_val[index_val] = val
+                return val
+            case unexpected:
+                assert False, f"Invalid assign target @ _assign(): {unexpected}"
```

`left_expr` の形によって処理を分けます。単なる識別子 `Ident()` の場合は従来の `assign` と同じように `Environment.assign()` を呼んで終わりです。

`(Ident("index"), [coll_expr, index_expr])` という形をしているときが本題で、`arr[2]` であれば `coll_expr` が `arr`、`index_expr` が `2` です。それぞれ評価して値にしてから `coll_val[index_val] = val` とすることで配列の要素に代入しています。


配列要素に代入する前に、左辺が配列でインデックスが `int` であることを確認しています。あまり厳密にエラーをチェックするつもりがない Toil では確認しなくてもいい（代入の時に Python のエラーになる）んですが、型チェッカーの警告除けのために書いています[^not-very-strict]。

[^not-very-strict]: `isinstance()` でチェックしているため `arr[True] = 3` のような式が許されてしまいますがご愛敬。`type()` でチェックすれば確実に `int` であることが確認できるのですが、型の警告が消えなかったので現状のようにしてあります。「1.5 変数の定義と参照」の「コラム：True と False の値」も参照ください。

実行例です。

```py
    # Example

    print("Assign to an array element:")

    print(toil.ast(r""" arr[2] = 3 """)) # -> (assign, [(index, [arr, 2]), 3])
    print(toil.walk(r""" arr := [2, 3, 4]; arr[2] = 5 """)) # -> 5
    print(toil.walk(r""" arr """)) # -> [2, 3, 5]
    print(toil.walk(r""" arr[-1] = 6; arr """)) # -> [2, 3, 6]
```

ちゃんと動いています。`arr[2] = 5` の値は `5` であって `[2, 3, 5]` ではありません。代入は右辺の値を返すからです。インデックスが `-1` のときも Python 風に動いてますね。Python におまかせだからです。

```py
    print(toil.ast(r""" arr2[0][1] = 5 """))
    # -> (assign, [(index, [(index, [arr2, 0]), 1]), 5])
    print(toil.walk(r""" arr2 := [[2, 3], 4]; arr2[0][1] = 5; arr2 """))
    # -> [[2, 5], 4]
```

配列が入れ子になっても正しく代入できています。`(index, [arr2, 0])` が内側の `[2, 3]` を指しますので `(assign, [(index, [(index, [arr2, 0]), 1]), 5])` は `[2, 3]` の 2 つめの要素に `5` を代入するという動きになります。内側の `index` は配列の参照に、外側の `index` は配列要素への代入に、と異なる使われ方をしていることに注意してください。


```py
    print(toil.walk(r""" a := [2, 3]; b := [4, 5]; a[0] = b[1] = 6; [a, b] """))
    # -> [[6, 3], [4, 6]]
```

`=` は右結合で右辺の値を返すので、配列要素への代入も連鎖して書くことができます。

```py
    # toil.walk(r""" tpl := tuple(2, 3, 4); tpl[2] = 5 """)
    # -> Invalid index assignment
    # toil.walk(r""" arr := [2, 3]; arr[None] = 4 """)
    # -> Invalid index assignment
    print(toil.walk(r""" arr := [2, 3]; arr[True] = 4; arr """))
    # -> [2, 4]
```

警告除けで書いたチェックも動いています。ついでに `arr[True] = 4` も想定通り？動いてますね。

最後に、配列の操作が一通りできるようになったので、エラトステネスの篩で素数を探してみます。

エラトステネスの篩とは、ざっくり言うと 2 から始めて 2 は素数、そのあと 2 で割り切れる数は素数ではないとマークして、残った数のなかで一番小さい 3 は素数、そのあと 3 で割り切れる数は素数ではないとマークして・・・という作業を繰り返して、残った数字が素数です、というやりかたです。ここでは配列の操作がちゃんとできていることを見るのが主眼なので中身わからなくても大丈夫です[^efficient-sieve]。

[^efficient-sieve]: わりとマジメに余分な計算をしないようにした書き方なので、「ざっくり言うと」で説明したのよりも少々わかりづらいかもしれません。特に `j := i * i; while j < n do` のあたり。詳しくはアルゴリズムの本や記事でも探していただいて。

```py
    toil.walk(r"""
        def sieve(n) do
            s := [False, False] + [True] * (n - 2);
            i := 2; while i * i < n do
                if s[i] then
                    j := i * i; while j < n do
                        s[j] = False;
                        j = j + i
                    end
                end;
                i = i + 1
            end;

            primes := [];
            i := 0; while i < n do
                if s[i] then push(primes, i) end;
                i = i + 1
            then primes end
        end
    """)
    print(toil.walk(r""" sieve(10) """)) # -> [2, 3, 5, 7]
```

10 未満の素数（2、3、5、7）が正しく求められています。

これで配列が配列っぽく使えるようになりました。

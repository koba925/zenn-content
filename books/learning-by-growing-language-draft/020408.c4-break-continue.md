---
title: "4.8 break・continue"
---

`while` に `break` と `continue` をつけます。

どちらも、本来実行すべき順序を無視してどこかに飛んでいくという意味で `return` と似ています。実装も同じように例外を使います。Toil の while 式はループの最後に評価した式を while 式全体の値としていましたが、`break` したときの while 式の値は `None` とします。

まずは例外を送出する方の処理。

```diff py
 class ReturnException(Exception):
     def __init__(self, val: Value = None) -> None: self.val = val
 
+class BreakException(Exception): pass
+class ContinueException(Exception): pass

 class Evaluator:
     def eval(self, expr: Expr, env: Environment) -> Value:
         match expr:
             ...
             case Ident("return"): raise ReturnException(None)
+            case Ident("break"): raise BreakException()
+            case Ident("continue"): raise ContinueException()
             case Ident() as ident: return env.val(ident)
             ...
```

例外は `_while()` で受け取ります。`ContinueException` だったら `continue` します。`break` だったら `return None` でループを抜けつつ `None` を返します。

```diff py
     ...

     def _while(self, cond_expr, body_expr, env):
         val = None
-        while self.eval(cond_expr, env): val = self.eval(body_expr, env)
+        while self.eval(cond_expr, env):
+            try:
+                val = self.eval(body_expr, env)
+            except ContinueException: continue
+            except BreakException: return None
         return val

     def _op(self, op_expr, args_expr, env):
         ...

```

`Interpreter.eval()` まで例外が上がってきたらエラーにします。

```diff py
class Interpreter:
     ...

     def eval(self, expr: Expr) -> Value:
         try:
             return Evaluator().eval(expr, self._env)
         except ReturnException as e: return e.val
+        except ContinueException: assert False, "Continue at top level @ eval()"
+        except BreakException: assert False, "Break at top level @ eval()"

     ...
```

実行例です。

```py
    print("Break and continue:")

    print(toil.ast(r""" break """)) # -> break
    print(toil.ast(r""" continue """)) # -> continue
```

`break` や `continue` は単なる識別子として扱います。

```py
    print(toil.walk(r""" while True do break end """)) # -> None
```

最も単純なテスト。無限ループにもならずちゃんと `None` が返っています。

```py
    print(toil.walk(r"""
        i := 0; while i < 4 do
            print(i);
            i = i + 1
        end
    """)) # -> 0\n1\n2\n3\n4

    print(toil.walk(r"""
        i := 0; while i < 4 do
            if i == 1 then i = 2; continue end;
            print(i);
            if i == 3 then break end;
            i = i + 1
        end
    """)) # -> 0\n2\n3\nNone
```

ひとつめの実行例は while 式のループ自体がちゃんと動くことの確認です。ふたつめで `continue` と `break` 両方使っています。

```py
    print(toil.walk(r"""
        i := 0; while i < 2 do
            j := 0; while j < 3 do
                print(i, j);
                j = j + 1
            end;
            i = i + 1
        end
    """)) # -> 0 0\n0 1\n0 2\n1 0\n1 1\n1 2\n2

    print(toil.walk(r"""
        i := 0; while i < 2 do
            j := 0; while j < 3 do
                print(i, j);
                if i == 0 and j == 1 then break end;
                j = j + 1
            end;
            i = i + 1
        end
    """)) # -> 0 0\n0 1\n1 0\n1 1\n1 2\n2
```

二重ループのテスト。内側のループだけを抜けています。

```py
    print(toil.walk(r"""
        def check_and_quit(i) do
            if i == 2 then break end
        end;
        i := 0; while True do
            check_and_quit(i);
            print(i);
            i := i + 1
        end
    """)) # -> 0\n1\nNone
```

いったいこれは何でしょう？ちょっとありえなさそうなコードですが。

はい、普通の言語ならエラーです。

本来、`_op()` の try 文でも `BreakException` や `ContinueException` を捕捉するところなんですが手を抜いて補足しなかったのでそこではエラーにならず上位に伝播します。動かしてみると関数も抜けて最初に見つかった while 式で捕捉されているようです。チェック不足で裏技が生えたって感じですね。

おそらくこういった書き方はよいプラクティスとは言えないと思いますし、中間コードコンパイラに互換の動作をさせるのは難しそうですが、ちょっと面白いのでエラーチェックを増やさずに残しておきました。こんな書き方しなければいいだけですし。面白い使い方を思いついたりこれだとこういう場合に破綻しますよといった気づきがあったらぜひ教えてください。

```py
    # print(toil.walk(r""" break """)) # -> Break at top level
    # print(toil.walk(r""" continue """)) # -> Continue at top level
```

トップレベルの `break` や `continue` はさすがにエラーにしました。

ところで `break` したときに while 式の値が `None` にしかできないのはちょっと不自由な気がします。`break(2)` と書けば while 式の値を `2` にできる、というのもひとつのアイデアなんですが、ちょっと違うやり方を考えました。

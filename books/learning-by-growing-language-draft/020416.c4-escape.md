title: "4.16 エスケープ付き文字列"

raw 文字列だけでも用が足りることは多いのですが（Toil の raw 文字列は改行も入るし）、文字列中にシングルクォート入れたいなど、どうしても対応できないことが出てきます。本節ではエスケープシーケンスに対応した文字列を導入します。エスケープ付き文字列はダブルクォートで文字列を囲むことにします[^bash-style]。

[^bash-style]: bash の流儀です。好み＆慣れの問題かもしれませんがうまい使い分けのような気がしています。

今回は本当に字句解析だけの修正です。トークンになってしまえば raw 文字列もエスケープ付き文字列もただの `str` の値でしかないのでその後は全く同じ。

```diff py
 class Scanner:
     ...
 
     def tokenize(self) -> list[Token]:
         while (c := self._current_char()) != "$EOF":
             self._start_pos = self._current_pos
             match c:
                 ...
                 case "'": self._raw_string()
+                case '"': self._string()
                 case c if is_ident_first(c): self._ident()
                 ...
```

Toil 処理系の（Python）コードでは基本的に文字列はダブルクォートで囲んでいますが、ここでは `'"'` とシングルクォートで囲みました。`"\""` よりも見た目がキレイだからです。つまりただの好みの話です。統一感の方が大事な人は `"\""` でどうぞ。

```diff py
     def _raw_string(self):
         ...
 
+    def _string(self):
+        self._advance()
+        s = []
+        while (c := self._current_char()) != '"':
+            assert c != "$EOF", f"Unterminated string @ _string(): {c}"
+            if c == "\\":
+                self._advance()
+                c = self._current_char()
+                assert c != "$EOF", f"Unterminated escape sequence @ _string(): {c}"
+                match c:
+                    case "n": s.append("\n")
+                    case _: s.append(c)
+            else:
+                s.append(c)
+            self._advance()
+        self._advance()
+        self._tokens.append("".join(s))

     def _ident(self):
         ...
```

ダブルクォートを見つけたあとの処理ですが、先頭と末尾の位置を決めて `_src` から切り出すのとは違うやり方をしています。エスケープしたところは `_src` とは違う文字になってほしいので切り出して済ませることはできません。

代わりに、1 文字ずつ配列に `append()` していき、最後に `join()` でひとつの文字列にまとめています。`""` から始めて 1 文字ずつ足していけば素直ですが、Python の文字列はイミュータブルで、`+=` するたびに新しい文字列オブジェクトが生成されてしまうため、Python 的にはよくない書き方とされています。詳しくは「2.1 数を読む（字句解析）」の「コラム：Python の文字列」をどうぞ。

文字列を読んでいる間にバックスラッシュを見つけたらバックスラッシュ自体はスキップして、次に来た文字で処理を分けます。`"n"` だったら改行文字とみなして `s` に `"\n"` を追加し、それ以外であればそのまま今見ている文字を追加します。これにより `\"` はダブルクォートになり、`\\` はバックスラッシュになります。それ以外の文字も同様なのでたとえば `\x` はただの `x` になります。あと、バックスラッシュの次が `"$EOF"` だった時のチェックもしています。

実行例に進みます。

```py
    # Example

    print("String with escape:")

    print(toil.scan(r""" "abc" """)) # -> ['abc', $EOF]
    print(toil.walk(r""" ["abc"] """)) # -> ['abc']
    print(toil.walk(r""" [""] """)) # -> ['']
    print(toil.walk(r""" ["if ; #'"] """)) # -> ["if ; #'"]
    print(toil.walk(r""" ["a
b"] """)) # -> ['a\nb']
```

このあたりは raw 文字列とほとんど同じですが、ダブルクォートで囲んだ文字列の中ではシングルクォートが普通に書けていることに注意してください。

```py
    print(toil.walk(r""" ["a\nc"] """)) # -> ['a\nc']
    print(toil.walk(r""" ["a\\c"] """)) # -> ['a\\c']
    print(toil.walk(r""" ["a\"c"] """)) # -> ['a"c']
    print(toil.walk(r""" ["a\xc"] """)) # -> ['axc']
```

エスケープシーケンスの処理です。想定通りですね。

```py
    # toil.walk(r""" " """) # -> Unterminated string
    # toil.walk(""" "a\\""") # -> Unterminated escape sequence
```

2 番目の実行例は、文字列中のバックスラッシュでプログラムが終わってしまう例です。raw 文字列で `r""" "a\"""` と書けばよさそうなものですが、raw 文字列でも引用符だけはバックスラッシュでエスケープされるのでこうは書けないのです。統一性の面からはちょっと悔しいのですがここだけ普通の文字列にしてエスケープシーケンスでバックスラッシュを書いています。

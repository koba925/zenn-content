`not` を作ったので `and` と `or` を作りましょう。

`and` と `or` は二項演算子だから比較演算子を追加したようにやればできるのでは・・・と思うかもしれませんが `and` と `or` は特殊なのです。ここはちょっと説明しておく必要があります。わかっている方はスキップしてかまいません。

`and` を例にとって説明します。

`and` といえばまず `a == 2 and b == 3` のように真偽の判断をする式を並べ、両方とも真だったら真、そうでなければ偽、というイメージだと思います。では、 `a != None and a.foo()` や `a != 0 and 4 // a` のような式を見たことがあるでしょうか。`a and a.foo()` のような形だったかもしれませんがほぼ同じ意味です（どういうこと？と思ったら「[1.4 ifを評価する](https://zenn.dev/kb84tkhr/books/learning-by-growing-language/viewer/c1-if)」の「[コラム：TruthyとFalsy](https://zenn.dev/kb84tkhr/books/learning-by-growing-language/viewer/c1-if#%E3%82%B3%E3%83%A9%E3%83%A0%EF%BC%9Atruthy%E3%81%A8falsy)」を読んでおいてください）。これらは「`a` が `None` でなければ `a.foo()` を実行してその結果を返す」式だったり「`a` が `0` でなければ `4 // a` を返す」式だったりします。`and` の左辺で変数をチェックしてから右辺を評価する、という意味合いです。

Python で試してみましょう。

```py
>>> a = 0; a != 0 and 4 // a
False
>>> a = 2; a != 0 and 4 // a
2
>>> a = 0; a and 4 // a
0
>>> a = 2; a and 4 // a
2
```

これらから、以下のようなことがわかります。

* `True` や `False` を返すとは限らない
* `and` の左の式が偽であれば右の式は実行しない

さらに具体的には、`A and B` は `if A then B else A end`、日本語にすれば「`A` が真なら `B`、そうでなければ（`B` は放置して）`A`」という意味なのです。右の式は実行しないで結果を返すことを短絡評価（Short Circuit）と言います。

「両方とも真だったら真、そうでなければ偽」という `and` のイメージからすると全然違うように見えるかもしれませんが、Truthy と Falsy の考え方と組み合わせるとこれでつじつまが合っているのです。今度は `a == 2 and b == 3` で考えてみましょう。`A and B` で言えば `A` が `a == 2`、`B` が `b == 3` ということです。

| `a` | `b` | `A` つまり `a == 2` | `B` つまり `b == 3` | `a == 2 and b == 3` |
| :---: | :---: | :---: | :---: | :---: |
| 2 | 3 | `True`（もちろん真） | `True` | `B` つまり `True` |
| 2 | 2 | `True`（もちろん真） | `False` | `B` つまり `False` |
| 3 | 3 | `False`（もちろん偽）| 評価しない | `A` つまり `False` |
| 3 | 2 | `False`（もちろん偽）| 評価しない | `A` つまり `False` |

となります。ていねいに見ていけばちゃんとイメージと合う結果になっていることがわかると思います。

前置きはこれくらいにして、ここで仮に `self._env.define(Ident("and"), lambda args: args[0] and args[1])` として組み込み関数を追加する形で `and` を作るとどうなるでしょうか。`a != 0 and 4 / a` は `and(a != 0, 4 / a)` という組み込み関数の呼び出しと解釈され、処理系は `a != 0` と `4 / a` を評価してから `and()` に渡そうとします。が、`a` が `0` なので `4 / a` を評価しようとしたところで `ZeroDivisionError` になってしまいます。これでは `a != 0` をチェックするという意味がありません。

ではどのように実装するとよいでしょうか。

ここでまず考えてみたいのは、`def` を `:=` と `func` の組み合わせによって構文糖衣として実装したように、 `and` を `if` による構文糖衣として実装することです。なにせ `A and B` は `if A then B else A end` と同じだというのですから。

ところが実を言うと、この式では `A` が真のとき `A` を 2 回評価してしまうので全く同じ意味とは言えないのです。とってつけたような例ですが、`print(2) and a == 3` という式を考えてみましょう。 これを `if A then B else A end` にあてはめて変形すると `if print(2) then a == 3 else print(2) end` となります。`print(2)` は `None` を返すので偽と判定され、Else 節の `print(2)` が実行されます。結果、`2` が 2 回出力されてしまうことになります。これはおかしい。

そこも合わせようとするなら `if tmp := A then B else tmp end` などといったん別の変数に入れる方法があります。しかし今度は `tmp` という変数名が、実際に使われる変数とカブってしまうという問題が発生します。`a == 3 and tmp == b` のような式を評価しようとするとおかしなことになります。カブりにくい名前を使うという作戦もありますが本質的ではありません。

第 4 部でこの問題に立ち返りますが、ここでは `and` は構文糖衣とはせず、 `if` や `while` のように、`Evaluator` の中で個別に処理することとします。別の言い方をすると、`and` は関数ではなく制御構造として扱う、とも言えます。

以上の話は `or` にも同じように適用できて、`or` は `if A then A else B end` の意味となります。

では実装に入りましょう。

`and`・`or` の優先度は定義・代入と否定の間に置きます。普通は `and` と `or` の優先度は別にして、`and` を `or` よりも上の優先度に置くのですが、Toil では同じ優先度としました[^and-or-priority]。ちゃんと分けたい人はもう自分で分けられるでしょう。

[^and-or-priority]: それなりに数学的な背景もあったりするのですが、実際書いてるとどっちが上だっけ？となりがちなのでどっちみちカッコで明示したりするので・・・まあいいかなと・・・

```diff py
     def _define_assign(self):
         return self._binary_right({
             Ident(":="): Ident("define"), Ident("="): Ident("assign")
         }, self._and_or)
 
+    def _and_or(self):

     def _not(self):
```

本節のメインは `Evaluator` の修正です。上でした話をそのまま実装すると以下のようになります。

```diff py
class Evaluator:
     def eval(self, expr: Expr, env: Environment) -> Value:
         match expr:
             ...
             case (Ident("if"), [cond_expr, then_expr, else_expr]):
                 return self._if(cond_expr, then_expr, else_expr, env)
+            case (Ident("and"), [left_expr, right_expr]):
+                left = self.eval(left_expr, env)
+                if left:
+                    return self.eval(right_expr, env)
+                else:
+                    return left
+            case (Ident("or"), [left_expr, right_expr]):
+                left = self.eval(left_expr, env)
+                if left:
+                    return left
+                else:
+                    return self.eval(right_expr, env)
             case (Ident("while"), [cond_expr, body_expr]):
                 return self._while(cond_expr, body_expr, env)
             ...

     ...
```

この `if` と同じことをするのが `and` や `or` なので実際にはこう書けます。裏では上のようなロジックで動いているということは忘れないでください。

```diff py
class Evaluator:
     def eval(self, expr: Expr, env: Environment) -> Value:
         match expr:
             ...
             case (Ident("if"), [cond_expr, then_expr, else_expr]):
                 return self._if(cond_expr, then_expr, else_expr, env)
+            case (Ident("and"), [left_expr, right_expr]):
+                return self.eval(left_expr, env) and self.eval(right_expr, env)
+            case (Ident("or"), [left_expr, right_expr]):
+                return self.eval(left_expr, env) or self.eval(right_expr, env)
             case (Ident("while"), [cond_expr, body_expr]):
                 return self._while(cond_expr, body_expr, env)
             ...

     ...
```

長々と説明した割に修正はこれだけです。動かしてみましょう。

```py
    # Example

    print("And and or:")

    print(toil.walk(r""" True and False """)) # -> False
    print(toil.walk(r""" False and True """)) # -> False
    print(toil.walk(r""" True or False """)) # -> True
    print(toil.walk(r""" False or True """)) # -> True
```

ごく普通の `and`・`or` の動きです。

```py
    print(toil.walk(r""" True and 2 """)) # -> 2
    print(toil.walk(r""" 0 and 2 / 0 """)) # -> 0
    print(toil.walk(r""" False or 2 """)) # -> 2
    print(toil.walk(r""" 1 or 2 / 0 """)) # -> 1
```

短絡評価になっていることの確認です。Truthy や Falsy の話も思い出して。

```py
    print(toil.walk(r""" print(2) and 3 """)) # -> 2\nNone
    print(toil.walk(r""" not print(2) or 3 """)) # -> 2\nTrue
```

左辺が 2 回評価されないことを確認しています。

```py
    print(toil.walk(r""" True or False and False """)) # -> False  # (True or False) and False
    print(toil.walk(r""" False and False or True """)) # -> True   # (False and False) or True
```

左結合になっていることの確認です。`and` と `or` に優先度の差は付けていないのでした。

```py
    print(toil.walk(r""" not True and False """)) # -> False       # (not True) and False
    print(toil.walk(r""" False or not False """)) # -> True        # False or (not False)
    print(toil.walk(r""" a := True and False """)) # -> False      # a := (True and False)
    print(toil.walk(r""" a """)) # -> False
```

`and`・`or` の優先度が定義・代入と否定の中間になっていることを確認しました。

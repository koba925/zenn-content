ユーザ定義関数を作ります。大きく分けて３つの部分からなります。

* クロージャを作る
* クロージャを呼び出す
* 関数とトップレベル

上の２つが終わらないと３つめは意味が分からないのでまず上のふたつから説明します。

`Compiler` の修正から見ていきましょう。まずはクロージャを作るところから。

```diff py
class Compiler:
     ...
 
     def _expression(self, expr):
         match expr:
             ...
             case str(name): self._emit("get", name)
+            case ("func", [params, body_expr]): self._func(params, body_expr)
             case ("define", [name, expr]):
             ...

     ...

     def _while(self, cond_expr, body_expr):
         ...
 
+    def _func(self, params, body_expr):
+        body_code = Compiler(body_expr).compile()
+        self._emit("make_closure", params, body_code)
+
     def _scope(self, body_expr):
         ...
```

`("func", [params, body_expr])` という式を受け取ったら、`body_expr` をコンパイルして、`make_closure` という命令のオペランドにします。`compile()` 中に `compile()` を再帰的に呼び出していてなにか心配だという人もいると思いますが、新しい `Compiler` オブジェクトを作り、その中でコンパイルの処理を済ませられる（グローバル変数にアクセスしたりはしない）ので問題ありません。コンパイル結果をそのままオペランドにしているのも、ひとによってはびっくりするかもしれません[^native_compiler]。

[^native_compiler]: 機械語にコンパイルするような処理系になじみのある人だと、いやいやコンパイル結果はメモリ上に配置して関数の先頭アドレスを管理しなきゃいけないんじゃないの、と思うかもなーという想像です。コンパイル結果は配列に入っているので、中では結局 Python さんがメモリ上の配置を考えてアドレスを管理しています。

あと 1 か所修正があって、`compile()` ではコードの最後に `halt` ではなく `ret` をつけるようにします。`ret` は関数から帰る命令です。これがないと関数から戻ってこれません。


```diff py 
 class Compiler:
     ...

     def compile(self):
         self._expression(self._expr)
-        self._emit("halt")
+        self._emit("ret")
         return self._code

     ...
```

VM を見ていきます。

```diff py 
 class VM:
     ...

     def execute(self):
         while (inst := self._code[self._ip]) != ("halt",):
             self._ip += 1
             match inst:
                 ...
                 case ("jump_if_false", addr):
                     if not self._stack.pop(): self._ip = addr
+                case ("make_closure", params, body_code):
+                    self._stack.append(("closure", [params, body_code, self._env]))
                 case ("call", nargs): self._call(nargs)
+                case ("ret",): self._ret()
                 case _:
                     assert False, f"Invalid instruction @ execute(): {inst}"
         ...
 
     def _call(self, nargs):
         op = self._stack.pop()
         args = list(reversed([self._stack.pop() for _ in range(nargs)]))
-        self._stack.append(op(args))
+        match op:
+            case f if callable(f): self._stack.append(f(args))
+            case ("closure", [params, body_code, closure_env]):
+                self._ctrl_stack.append(("call", self._code, self._ip, self._env))
+                self._env = Environment(closure_env)
+                self._env.bind(params, args)
+                self._code = body_code
+                self._ip = 0
+            case _:
+                assert False, f"Invalid operator @ _call(): {op}"
 
+    def _ret(self):
+        _, self._code, self._ip, self._env = self._ctrl_stack.pop()
 
 class Interpreter:
     ...
```

`make_closure` では、`params`・`body_code` に加えて `_env` を記録することでクロージャを作ります。`eval()` でクロージャを作っているところとそっくりです。

```py
            case ("func", [params, body_expr]):
                return ("closure", [params, body_expr, env])
```

`_call()` では `op` の形で処理を分けます。

`callable` なときは組み込み関数の処理です。

クロージャだったときは以下のように動きます。

* `_ctrl_stack` に現在の `_code`、`_ip`、`_env` を記録します。これは関数から戻ってくるために使います。`scope` から出るときのために `_env` を覚えておいたのと同じです。`_scope` が積んだものと区別できるようにタプルの先頭に `"call"` を置いています[^not-checked]。
* 新しい環境を作り、`params` と `args` を `bind()` します。`bind()` は、仮引数と実引数からローカルな変数を定義するのでしたね。
* 仮想マシンのコードを関数のコード（`body_code`）に置き換え、`_ip` を 0 にします。これで、ループを次に回るときは関数のコードが先頭から実行されることになります。

[^not-checked]: 第 1 部の段階では、実際には `"scope"` や `"call"` を見てどちらの情報か区別することはしていません。これは、`scope` や関数呼び出しが完全に入れ子構造にしたがうので、スコープから出るときは `"scope"` が、関数から戻るときは `"call"` がスタックの最上位にいることが確実だからです。

これも `eval` でクロージャを使って関数呼び出しを実行しているところと見比べてみると面白いでしょう。

```py
            case ("closure", [params, body_expr, closure_env]):
                new_env = Environment(closure_env)
                new_env.bind(params, args_val)
                return self.eval(body_expr, new_env)
```

なお、仮想マシンの環境やコードを置き換えて関数を実行するというメカメカしいやりかたではなく、関数のコンパイルの時のように `body_code` と `closure_env` から新たな `VM` オブジェクトを作って再帰的に `execute()` するというやりかたもあって、それはそれできれいなやり方なんですが、状態を取っておいてあとで戻す、というやり方を知っておくのも大事かなと思ってそうしています[^another-aim]。

[^another-aim]: もうひとつ狙いがあるんですが、本書では扱いません。継続（Continuation）という機能なんですが、筆者の遊びネタになる予定。気になったら検索でもしてみてください。

`ret` 命令だったら `_ctrl_stack` から呼び出し時に覚えておいた `_code`、`_ip`、`_env` を取り出して戻します。これで呼び出したときの次の命令から実行が再開します。`_ip` は命令を読むとすぐに次の命令を指す（`self._ip += 1`）ことを思い出してください。

さて、これで大部分説明できたんですが「関数とトップレベル」の話が残っています。トップレベルというのは関数に入っていない部分のコードのことなんですが、現在の `compile()` だとこういった関数に入ってないコードの最後にも `ret` がついてしまいます。

```
print(2);
print(3)
```

関数の外では `_ctrl_stack` が空なので、`ret` が `_ctrl_stack` から `_ip` などを取ろうとするとエラーになってしまいます。

これを以下のように解決しています。

```diff py
 class VM:
     def __init__(self, code, env):
         ...
         self._stack = []
-        self._ctrl_stack = []
+        self._ctrl_stack: list = [("call", [("halt",)], 0, env)]

     ...
```

こうしておくと、あたかもあとは `halt` するだけの関数から呼ばれたような状態でトップレベルの実行がスタートするので、トップレベルから `ret` してもつじつまが合うようになります。

`halt` で終わる `compile()` と、`ret` で終わる `compile_func()` に関数を分けるなどしてストレートに解決する方法に比べるとちょっと小手先感はあるのですが、ある意味実際のコンパイラに似てるところもあるなと思ってこのやり方にしました。というのは、C のような言語だと、プログラムを実行するときにいきなり自分が書いたコード（C の場合は `main()`）が走り出すのではなく、「ランタイム」と呼ばれるものがプログラムの実行環境を整えて、その上でユーザの書いたコードを呼び出すという形になっているからです。`("call", [("halt",)], 0, env)` が超小型のランタイムと言えなくもないなと。こじつけですけど。まあこっちのほうが行数増えないし。

実行例です。

```py
    print("Functions:")

    print(toil.ast(r""" func do 2 end ()"""))
    # -> (('func', [[], 2]), [])
    print_code(toil.code(r""" func do 2 end ()"""))
    # ->   0: ('make_closure', [], [('const', 2), ('ret',)])
    # ->   1: ('call', 0)
    # ->   2: ('halt',)
    print(toil.run(r""" func do 2 end () """)) # -> 2

    print(toil.ast(r""" func a do a + 2 end (3) """))
    # -> (('func', [['a'], ('add', ['a', 2])]), [3])
    print_code(toil.code(r""" func a do a + 2 end (3) """))
    # ->   0: ('const', 3)
    # ->   1: ('make_closure', ['a'], [('get', 'a'), ('const', 2), ('get', 'add'), ('call', 2), ('ret',)])
    # ->   2: ('call', 1)
    # ->   3: ('halt',)
    print(toil.run(r""" func a do a + 2 end (3) """)) # -> 5

    print(toil.ast(r""" func a, b do a + b end (2, 3) """))
    # -> (('func', [['a', 'b'], ('add', ['a', 'b'])]), [2, 3])
    print_code(toil.code(r""" func a, b do a + b end (2, 3) """))
    # ->   0: ('const', 2)
    # ->   1: ('const', 3)
    # ->   2: ('make_closure', ['a', 'b'], [('get', 'a'), ('get', 'b'), ('get', 'add'), ('call', 2), ('ret',)])
    # ->   3: ('call', 2)
    # ->   4: ('halt',)
    print(toil.run(r""" func a, b do a + b end (2, 3) """)) # -> 5

    print(toil.run(r"""
        twice := func f, x do f(f(x)) end;
        double := func x do x * 2 end;
        twice(double, 3)
    """)) # -> 12

    print(toil.run(r"""
        a := 2;
        f := func do a end;
        g := func do a := 3; f() end;
        g()
    """)) # -> 2

    print(toil.run(r"""
        func a do func b do a + b end end (2)(3)
    """)) # -> 5

    # toil.run(r""" 2(3) """) # -> Invalid operator
```

本書は Toil [^toil]というプログラミング言語を作りながら、プログラミング言語処理系の原理を学ぶための本です。ソースコードを処理して実行するプログラムをプログラミング言語処理系と呼ぶのですが、ちょっと長いので本書では言語処理系・処理系などと呼ぶことにします。

[^toil]: 趣味で作るおもちゃのような言語をトイ言語と呼びます。Toil という名前は TOI Language から来ています。英語では「重荷」という意味ですがそういうつもりではありません。

プログラミング言語ってどうやって動いてるんだろう？と興味を持っている人に向けて書きました。Python をすこし覚えて、配列[^list]（`[2, 3, 4, ...]`）や辞書（`{"a": 2, "b": 3, ...}`）を使ったり自分でクラスを作ったことがある、くらいの人が読んでいるところを思い浮かべて書いています。

[^list]: Python 用語では「リスト」ですが、本書では他の言語でも使われる用語である「配列」を使っていきます。

難しいかなと思ったところは簡単に説明しながら進めますし、もともとそれほどややこしい機能は使いませんので安心して読み進めていただけると思います。知ってる方は適宜読み飛ばしていただければ。

## 本書の特徴

本書ではごく小さなプログラムから始めて少しずつ機能を付け足しては動かすことを繰り返すことでプログラミング言語の作り方を学習していきます（こういう開発の進め方をインクリメンタルな開発と言います）。

本書で作るのはインタプリタ型のプログラミング言語です。「インタプリタ」というのは、すごくざっくり言うとソースコードを読んですぐ実行する処理系のことです。対となる言葉は「コンパイラ」で、こちらはいったんソースコードを他の形式に変換しておき、実行時にはその変換したものを使う処理系を指します。このあたりは細かいことに踏み込むと長くなってしまうのでこれくらいで。

:::message
この本は理論や用語にはあまり深く踏み込まず、だいたいこれくらいのざっくりさで雰囲気をつかむ程度の説明でいきます。ただ、用語についてはその後の学習につながるよう、一般的な用語を使います。初めて出てくる用語はかんたんに説明するようにしますが、すこし難しく聞こえる言葉もあるかもしれません。あまり気にせず先へ進んでみてください。実例を見ているうちにイメージがつかめてくると思います。
:::

Sample1 は Toil のソースコードで、階乗（1 から $n$ までをかけ算した数）を求めるものです。ちょっと見慣れないところもあるけどなんとなく読めるしプログラミング言語だな、と思えるのではないでしょうか？

```text:Sample1
    def factorial_iter(n) do
        result := 1;
        while n > 0 do
            result = result * n;
            n = n - 1
        end;
        result
    end
```

これを動かすための処理系は第 2 章で作成しますが、たった 350 行程度の Python でできています。えっそんなもんなの？という感じではないでしょうか？動かすための原理的な部分に集中すれば実はそれくらいで動いてしまうのです。

第 2 章？じゃあ第 1 章は？ってなりますよね。第 1 章ではインタプリタのコアとなる部分を作ります。このコア部分だけで上と同じアルゴリズムが実行できます。コア部分だけならなんと 100 行程度！ただしソースコード（？）は Sample2 のように書いてあげる必要があります。

```py:Sample2
    ("define", ["factorial_iter", ("func", [["n"], ("seq", [
        ("define", ["result", 1]),
        ("while", [("greater", ["n", 0]), ("seq", [
            ("assign", ["result", ("mul", ["result", "n"])]),
            ("assign", ["n", ("sub", ["n", 1])]),
        ])]),
        "result"
    ])])])
```

一瞬びっくりすると思いますが、Sample1 と見比べながら読むとなんとなく雰囲気はわかるのではないでしょうか？第 1 章で少しずつ作ったり動かしているうちに読めるようになってくるはずなので今はわからなくても問題はありません。第 1 章が終わってもこれを書く面倒さには慣れないかもしれませんが、Sample1 のようなソースコードを読んで自動的に Sample2 のように変換するのが第 2 章の目的なので、第 2 章に入れば書く必要はなくなります。

とにかくいろいろ動くようになるのが一番楽しいだろう、というのが根底にあって、このようにインタプリタのコアから始めるという構成にしました。ここがほかにはない本書の特徴だと思っています。

第 3 章では第 1 章とは異なるやりかたでプログラムを動かします。ソースコードを中間コードに翻訳するコンパイラと、その中間コードを実行する仮想マシンを組み合わせてプログラムを動かす、というものです。この本はインタプリタに関する本ですが、中間コードへとは言えコンパイルするのでコンパイラの処理の片鱗を見ることもできます。

いろいろ動くのが楽しいはず、という方針を継続し、その後も様々な機能を追加して最終的には以下のような機能を持つようになります。

* `None`、`bool`、整数、配列、タプル、辞書のデータ型
* 制御構造（if、while、for、break、continue）
* 変数とスコープ
* 組み込み関数・ユーザ定義関数・クロージャ
* 分割代入・パターンマッチ
* 例外処理
* パイプライン・オブジェクト指向（風）記法
* マクロ・カスタム文法

## 全体の構成と読み進め方

本書はインクリメンタルに開発を進めていきますので、順番に読むことを想定しています。ある程度わかっているから興味のあるところだけ読む、という読み方ももちろんしていただいてかまいませんが、用語や Python の機能については初出時に説明するようにしていたり、コードを差分形式で書いたりしているため、若干読みづらくなる可能性があります。

全体の構成は以下のようになっています。

* はじめに
* 第 1 部　最小のインタプリタ
  機能を最小限に絞り、ツリーウォーク式インタプリタ・中間コード式インタプリタというふたつの方式で小さなインタプリタを作ります。
  * 第 1 章　最小の評価器 (100 行程度)
    ツリーウォーク式インタプリタのコア部分を作り、アルゴリズムを実行できるようにします。  
  * 第 2 章　最小の字句解析・構文解析器 (350 行程度)
    テキストのソースコードを読んで、第 1 章の評価器で読めるようにする字句解析・構文解析器を作ります。
  * 第 3 章　最小の中間コード式インタプリタ [^bytecode]  (500 行程度)
    第 1 章の評価器の代わりに動く、ソースコードを中間コードに翻訳するコンパイラおよびその中間コードを実行する仮想マシンを作ります。
* 第 2 部　ツリーウォーク式インタプリタの拡張（以下未稿）
  ツリーウォーク式インタプリタに機能を追加していきます。第 2 部が終わると機能だけはわりと最近のスクリプト言語に近いレベルになります。
  * 第 4 章　基本のインタプリタ
    配列型・文字列型・タプル型を導入し、制御構造を強化します。ここまでくらいで自作プログラミング入門としては十分な機能と言えます。
  * 第 5 章　辞書
    辞書型を導入します。ドット記法を使ってパイプライン的記述・メソッド的記述ができるようにします。
  * 第 6 章　パターンマッチ
    関数の可変長引数から始めて分割代入・match 文・アロー関数などパターンマッチを使った各種機能を導入します。
* 第 3 部　メタサーキュラー
  Toil で Toil 自身を扱う方法を学びます。
  * 第 7 章　メタサーキュラー構造
    `eval()` や `apply()` を導入したり、Toil 言語で Toil 処理系を書いたりします。
* 第 4 部　拡張可能な言語
  Toil で Toil を拡張できるようにします。
  * 第 8 章　ファーストクラスマクロ
    マクロを導入し、処理系自体に手を入れなくても Toil の機能を拡張できるようにします。マクロの原理を学ぶため、まずは簡易な方式(評価中にマクロを展開する)で実装します。
  * 第 9 章　カスタム文法
    マクロの呼び出しを、if や while といった構文と同じようなスタイルで書けるようにする文法カスタマイズ機能を導入します。
  * 第 10 章　事前展開型マクロ
    あらかじめマクロを展開してから評価器に渡す、より本格的なマクロを実装します。
* 第 5 部　中間コード式インタプリタの拡張
  第 2 部・第 3 部で行った機能拡張を、今度は中間コード式インタプリタで行います。
* 第 6 部　ツリーウォーク式インタプリタと中間コード式インタプリタの協調動作
  これまでツリーウォーク式インタプリタと中間コード式インタプリタはほぼ独立に動作していましたが、協調して動作できるようにします。
  * ツリーウォーク式インタプリタの関数から中間コード式インタプリタの関数を呼んだり、その逆をできるようにします。
  * ツリーウォークインタプリタを実行中に関数をコンパイルできるようにします。
  * 最後は JIT モドキを作って完成となります。

[^bytecode]: インタプリタ実装の文脈では「バイトコード」という言葉の方がよくつかわれているかもしれません。本書では中間コードを「バイト」にしないので「中間コード」と呼んでいます。

おすすめの読み方は、一度ざっと読んだら自分で書いてみることです。読むだけでもそれなりの理解はできますが、自分で書いてみることにより飛躍的に理解度が上がります。「あれ、ここどうなってたっけな？」と思ったらすぐに書籍を見てかまいません。自分で書いてみるというところが大切で、わかったつもりのところが実はわかってなかった、というところがたくさん見つかるでしょう。それからもう一度書籍のコードを見ることで理解が進みます。

私自身、わかってると思ってたのにまったく書けなくて愕然としたことがあります。

いきなり自分で書くのは難しすぎる、という場合はじっくり読んでから再挑戦したり、いわゆる「写経」をしてみるのも手でしょう。掲載されているコードをひたすら書き写す、というやつです。その後、もう一度自分で書けるかどうかやってみてください。

本書のサンプル通りに書いたら、ちょっと改造してみるというのもよい練習になります。修正したままにして先へ進むとその先で動かなくなってしまうかもしれないので、コピーして別のところでやるとかブランチを切って試すとかしてもとのコードは残しておいてください。

この書籍では、第 1 部を読むだけでインタプリタ処理系の全体像がつかめるようになっています。ざーっと第 1 部の最後まで眺めたら、第 1 章を読んで書いてみる、第 2 章を読んで書いてみる、のように小刻みに進めてみるとよいと思います。なんなら第 1 章だけ読んで書いてみる、でも。

第 1 部を理解できればもう自分で言語を拡張したり、1 から自分の言語を書いたりすることもできるはずです。第 2 部以降を読んで書いてみるというのはもちろんですが、先に自分で書いてみるのも面白いかと。

あと、ところどころ章末にコラムを挟んでいますが、読み飛ばしても大丈夫です。興味があるところだけどうぞ。

## なぜPythonなのか

広く普及していて Python なら読み書きできるという人が多いというのは大きな理由の一つですが、それだけではありません。

インタプリタを作りましょうという本や記事はたいてい C 言語や Java（最近は Rust も？）など、高速な部類の言語を使っています。インタプリタの性能はそれを書いた言語の速度に直接影響を受けてしまうためです。残念ながら Python の実行速度は速いとは言えず、本来はインタプリタを書くのには適していません。にもかかわらず本書で Python を使うのは、（自作言語に限らず）学習には Python が最適だと考えているからです[^not-perfect]。

[^not-perfect]: Python が完璧とも思ってなくていろいろと言いたいこともあるんですが、あるんですがっていうかコラムで言いました！

Python はアルゴリズムを自然に見やすく書けるだけの機能が十分にそなわっており、かつ型などを書かなくてもよいため、プログラムに表現したいことだけを素直に書くことができます。

アルゴリズムを教えるとき、読みやすさを重視して「疑似コード」と呼ばれる架空の言語で説明するときがあります。Python のプログラムは、ほとんどこの「疑似コード」に近い読みやすさで、かつ実際に動かすことができるため、学習には最適の言語と言えます。

## 本書でやらないこと

本書はコンパクトなプログラムで Toil を動かすことを狙っているので、それ以外のことはいさぎよく切り捨てています。これらについては別の書籍で学ぶなり自力でがんばってみるなりしてください。

* 静的型
  Toil は動的型付け言語、ざっくりいうと実行するときに変数の型が決まる言語です。実行前に型が決まっていて型のチェックを行ったりする静的型付けの手法は含まれていません。
* メモリ管理
  変数、配列などを記憶するメモリをどう獲得してどう配置し、いらなくなったメモリをどう破棄するか[^gc]というのも大事な話なのですが本書では扱いません。そのあたりは Python にまかせています。ということでそのあたりの勉強はほかでやっていただく必要があります。
* エラー処理
  Toil では、エラーを見つけたら即停止で、行番号も教えてくれません。実用的な処理系では、1 回の実行（コンパイラなら 1 回のコンパイル）でできるだけ多くのエラーを見つけ、できるだけわかりやすく表示することが大切です。
* 堅牢性
  静的型付けではないという点も関連しますが、Toil は想定外のソースコードに対して「適切に」終了することについては注意を払っていません。たとえば `1 / 0` など実行すればエラーになる式もチェックせずに実行するので、Toil のエラーではなく Python のエラーで止まります。正しい入力に対しては正しく動くという点については注意するけれども、不正な入力について適切なエラーになるかどうかは気にしていない、とも言えます。
  Python のエラーで止まってしまうかもしれないし、想定外の動きをしてしまうかもしれません。実用的な処理系では、自分でチェックして適切にエラー処理を行うことが大切です。
* 性能
  先ほど書いた通り、Python で書いているので性能は推して知るべしです。高速な処理系にしたければ高速な言語で。

[^gc]: ガベージコレクション（Garbage Collection: GC）と呼ばれます。できることならやりたい話題なんですが処理系を根底から書き直すことになるので見送っています。もともと性能は度外視しているとはいえ、Python ではさすがに処理速度的にも厳しいかなあ・・・

## ソースコードの入手と動作環境

本書のソースコードは https://github.com/koba925/toil-book/ から入手できます。節ごとにタグがつけてありますので、任意の節のソースコードを表示できます。GitHub 上でタグを選んで表示していただいてもいいですし、節ごとに URL を記載していますのでそちらから開いても大丈夫です。

:::message
リポジトリを clone しておくと任意の節のソースを手元で表示・実行できて便利ですが、ひとつ注意事項があります。このリポジトリは、執筆の都合上、ソースに変更があった場合**予告なく履歴の書き換え（Force Push）を行います**。そのため後日 pull するとコンフリクト（競合）エラーが発生する可能性があります。更新したいときには再度 clone からやりなおすことをお勧めします。
「Download ZIP」であればそのような心配はありませんが、節ごとにダウンロードする必要があります。
:::

環境は Windows でも Linux でも Mac でもかまいませんが、Python 3.12 以降が使えるようにしてください。それより古いバージョンだとエラーが出ます。Python のバージョンを調べるにはコマンドプロンプトやターミナルで `python --version` を実行します。お使いの環境によっては `python3 --version` としないといけないかもしれません。

```
$ python --version
Python 3.12.13
```

3.11.xx 以下だったら Python をバージョンアップしてください。

処理系を動かすためには `pip` でインストールするような外部ライブラリは不要ですが、GitHub 上には Pytest を使ったテストコードも置いてあります。テストコードも動かしたい場合は `pip install pytest` で Pytest をインストールしてください。

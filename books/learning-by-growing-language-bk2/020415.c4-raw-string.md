文字列を導入します。文字列は `[]` で特定の位置の文字にアクセスできるのでコレクションの仲間です。Python の文字列は一度作ったら `s[2] = "a"` のように変更することができないので、配列よりもタプルに近い性質を持ちます。Toil もこの仕様を引き継ぎます。

Toil ではシングルクォートとダブルクォートで違った意味を持たせ、シングルクォートでくくった場合はエスケープ（`\n` のようなもの）の処理を行わないこととします。Python の raw 文字列（`r"..."`）相当です。まず単純なこちらから実装します。

扱う型が増えたので、型の定義に `str` を追加します。文字列はトークンでも AST でも値でもそのまんま文字列（`str`）です。

```diff py
 ...

 from typing import Callable
 
-type Token = None | bool | int | Ident
+type Token = None | bool | int | str | Ident
-type Expr = None | bool | int | Ident | tuple | list
+type Expr = None | bool | int | str | Ident | tuple | list
-type Value = None | bool | int | Callable | tuple | list

 type Instruction = tuple

```

今回のメインは字句解析です。その他はタプルで実装済みなところが多いので。とはいっても raw 文字列なのでそれほどややこしくはありません。

シングルクォートを見つけたら、次のシングルクォートを見つけるまで読み進め、見つかったところでレクシムを切り出してそのままトークンとします。シングルクォートが出てこないでコードの最後に達してしまったらエラー。

細かいところでは、最初にシングルクォートを見つけたら `_advance()` してから `_start_pos` を書き換えているところ、文字列最後のシングルクォートを見つけたら `_advance()` するまえにレクシムを切り出しているところに注意してください。これにより、文字列にシングルクォートが含まれないようにしています。

シングルクォート内ではシングルクォート以外の文字はすべてそのまま扱われるので、改行文字も 1 つの文字としてそのまま使われます。

```
'1行目のテキスト
2行目のテキスト'
```

のように書けるということです。Python の `''' ... '''` みたいですね。

構文解析・評価では、トークンが文字列（`str`）だったら `int` などと同様そのまま返すだけ。

使ってみます。

```py
    # Example

    print("Raw string:")

    print(toil.scan(r""" 'abc' """)) # -> ['abc', $EOF]
    print(toil.walk(r""" ['abc'] """)) # -> ['abc']
```

ちゃんと文字列として扱われていますね。

わざわざ `[]` でくくっているのは、`print(toil.walk(r""" 'abc' """))` だとクォーテーションなしで `abc` と表示されてしまい、識別子の `abc` と見分けがつかないためです。配列の要素は `repr` の形式で出力されるので、文字列にはクォーテーションがつき、識別子と見分けられるようになります。

```py
    print(toil.walk(r""" [''] """)) # -> ['']
    print(toil.walk(r""" ['if ; #"\n'] """)) # -> ['if ; #"\\n']
    print(toil.walk(r""" ['a
b'] """)) # -> ['a\nb']
```

空文字列が正しく扱われていること、意味ありげな記号もそのまま扱われていること、改行も扱えることを見てください。

```py
    print(toil.walk(r""" [join(['a', 'b', 'c'], ' ')] """)) # -> ['a b c']
    print(toil.walk(r""" [format('Age: {}', 25)] """)) # -> ['Age: 25']
```

`join()` は 1 つめの引数に配列で与えられた要素を 2 つめの引数に指定された文字列でつないで 1 つの文字列にして返す関数です。Python なら `" ".join(["a", "b", "c"])` と、つなぐ文字を先に書くところなので注意してください[^awkward-join]。

[^awkward-join]: どうもこの書き方違和感があるんですけどどうですか？`["a", "b", "c"].join(" ")` と書きたくなりませんか？という気持ちを込めて順番を変えてみました。多くの言語では逆になっているようです。Python の言い分については https://docs.python.org/ja/3/faq/design.html#why-is-join-a-string-method-instead-of-a-list-or-tuple-method を参照。

`format()` は 1 つめの引数をテンプレートとして、2 つめ以降の引数を適用した文字列を作るものです[^format-details]。

[^format-details]: `format()` の細かいところは https://docs.python.org/ja/3/builtins/stdtypes.html#str.format を参照してください。

```py
    print(toil.walk(r""" len('abc') """)) # -> 3
    print(toil.walk(r""" ['abc' + 'def'] """)) # -> ['abcdef']
    print(toil.walk(r""" ['abc'[2]] """)) # -> ['c']
    print(toil.walk(r""" [slice('abcdef', 2, 4)] """)) # -> ['cd']
    toil.walk(r""" for c in 'abc' do print(c) end """) # -> a\nb\nc
```

パターンマッチの導入のスタートは、配列の形をマッチさせることから始めます。これは、`[a, [b, c]]` のようなパターンに `[2, [3, 4]]` といった値をマッチさせ、`a` を `2`、`b` を `3`、`c` を `4` に結びつけるということです。

なんかそういうのってやったことある気がしませんか？`[a, b, c]` と `[2, 3, 4]` から `a` を `2`、`b` を `3`、`c` を `4` にするのなら実は関数呼び出し時に `bind()` でやっています。具体的には `env.bind([a, b, c], [2, 3, 4])` ですね。また `[a, b]` と `[2, [3, 4]]` を `bind()` すれば `a` が `2`、`b` が `[3, 4]` になります。実はすでにかなり近いことをやっていたことがわかります。

ということで、まずは関数呼び出し時の仮引数と実引数のマッチから始めます。であれば修正は `Environment.bind()` だけです。

え、構文解析変えなくても `def foo(a, [b, c])` とか読めるの？と思った方、鋭いです。`_func()` や `_def()` が仮引数の並びを解析するときには `_comma_separated_exprs()` を使っているので、カンマで区切られた「式」を読んでいたのです。なのでこの場合 `a` という式と、カンマと、`[b, c]` という式を読んで配列に入れているわけです。変数名しか来ないはずだから、と `_comma_separated_idents()` として作っていたらここで修正が必要だったんですけど、ここは先回りしてあらかじめ式を読むようにしていたというわけです。

```diff py
 class Environment:
     ...

-    def bind(self, params: list[Ident], args: list[Value]) -> None:
-        for param, arg in zip(params, args):
-            self.define(param, arg)
+    def bind(self, pattern: Expr, value: Value) -> None:
+        match pattern:
+            case Ident() as ident: self.define(ident, value)
+            case list():
+                assert isinstance(value, list), \
+                    f"Pattern mismatch @ bind(): {pattern}"
+                self._bind_list(pattern, value)
+            case unexpected:
+                assert False, f"Unexpected pattern @ bind(): {unexpected}"
 
+    def _bind_list(self, pattern, value):
+        assert len(pattern) == len(value), \
+            f"Item counts mismatch @ _bind_list(): {pattern} {value}"
+        for sub_pat, sub_val in zip(pattern, value):
+            self.bind(sub_pat, sub_val)
```

まず、`params`、`args` という変数名を `pattern`、`value` に変更しています。パターンをマッチして変数に値を設定するということを明示するためと、分割代入や match 式で使うときに不自然にならないようにです。

`bind()` ではまず、`pattern` の形によって処理を分けます。`pattern` が `Ident`、つまり変数名であれば、`define()` を呼んで変数に `value` を結びつけます。`pattern` が配列のときは `value` も配列でないとマッチしようがないのでまずチェックして、配列であれば `_bind_list()` で配列のマッチを行います。

関数呼び出しの場合、これまでと同様に仮引数は必ず配列に入れて渡されます。今までは `[a, b, c]` とフラットな 1 段の配列しか渡されなかったのが、`[a, [b, c]]` のような入れ子の配列が渡されることもある、というだけです。

`bind()` に `[a, [b, c]]` というパターンと `[2, [3, 4]]` という値が渡された場合を例にとって考えてみます。

まずは `case list()` に入り、`value` も配列なので `_bind_list()` に進みます。`pattern` と `value` は両方とも配列であることは確認済みですので、要素数が一致することを確認して以前の `bind()` と全く同じ処理でパターンの配列内の要素（`sub_pat`）と値の配列の要素（`sub_val`）を対応付けていきます。まずは `a` と `2` ですので `self.bind(a, 2)` の呼び出しが行われます。`bind()` では `a` が `Ident` なので `case Ident() as ident` に進み、`define()` で `a` と `2` が結びつけられます。

その後 `_bind_list()` の for ループに戻り、2 つめの要素である `[b, c]` と `[3, 4]` を対象にして処理します。今度は `self.bind([b, c], [3, 4])` の呼び出しが行われ、あとは `a` と `2` を結びつけたのと同じようにして `b` と `3`、`c` と `4` が結びつけられます。

やってみましょう。

```py
    # Example

    print("List match:")

    print(toil.ast(r""" def foo(a, [b, c]) do print(a, b, c) end """))
    # -> (define, [foo, (func, [[a, [b, c]], (print, [a, b, c])])])
```

`(a, [b, c])` という仮引数の並びがちゃんと `[a, [b, c]]` と読まれてますね。

```py
    toil.walk(r""" def foo(a, [b, c]) do print(a, b, c) end """)
    toil.walk(r""" foo(2, [3, 4]) """) # -> 2 3 4
```

うまくいきました。

```py
    # toil.walk(r""" foo(2) """) # -> Item counts mismatch
    # toil.walk(r""" foo(2, 3) """) # -> Pattern mismatch
    # toil.walk(r""" foo(2, [3, 4], 5) """) # -> Item counts mismatch
```

引数の数が合わなかったり、配列を指定するはずのところで数を渡したりするとエラーです。

```py
    toil.walk(r""" def foo(a, [b, [c, d]]) do print(a, b, c, d) end """)
    toil.walk(r""" foo(2, [3, [4, 5]]) """) # -> 2 3 4 5
```

配列が入れ子になっても大丈夫。

あとは普通の関数呼び出しもちゃんとできているか確認しておきます。

```py
    print(toil.ast(r""" def foo(a, b) do print(a, b) end """))
    # -> (define, [foo, (func, [[a, b], (print, [a, b])])])
    toil.walk(r""" def foo(a, b) do print(a, b) end """)
    toil.walk(r""" foo(2, 3) """) # -> 2 3
    # toil.walk(r""" foo(2) """) # -> Item counts mismatch
    # toil.walk(r""" foo(2, 3, 4) """) # -> Item counts mismatch
```

問題ないですね。

ほとんど `bind()` を再帰呼び出しにするだけの変更でしたが、関数呼び出しで入れ子の配列パターンをマッチさせることができました。このあとは、関数呼び出し以外でもパターンマッチを使えるようにしたり、さらにいろんなパターンへのマッチを実現していきます。

## コラム：Python における引数のパターンマッチ

Python にはこのような引数のパターンマッチはありません、と書こうとして調べたところ、実は Python 2 のときには可能だったことを知りました。以下のように仮引数をタプルの形で書くことで引数のパターンマッチができていました。

```py
def foo(a, (b, c)): print a, b, c

foo(2, (3, 4)) # -> 2 3 4
foo(2, [3, 4]) # -> 2 3 4
```

Python 3 になるときにこの機能が削られてしまったのです。なんと！

背景としては、型ヒントやキーワード引数との相性が悪いことや、実際あまり使われていないことがあるようです。詳細は [PEP 3113 – Removal of Tuple Parameter Unpacking](https://peps.python.org/pep-3113/) をご覧ください。

Haskell や Rust などの言語では立派に引数のパターンマッチが機能していますので引数のパターンマッチ自体が悪いということではありません。特に Haskell では引数のパターンマッチは関数定義の重要な機能としてなくてはならないものになっています。

Python 3 ではたとえば以下のようにして受け取った後で分解する必要があります。

```py
def foo(a, bc):
    b, c = bc
    print(a, b, c)
```

```py
def foo(abc):
    match abc:
        case [a, [b, c]]:
            print(a, b, c)
```

`a, b = 2, 3` のような分割代入（Python ではアンパックと呼ばれています）や match 文は存在するのになぜ引数のパターンマッチはないんだろう？と思って調べてみたらこんな背景がありました、というお話でした。

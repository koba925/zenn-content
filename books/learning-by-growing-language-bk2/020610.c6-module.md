「5.3 ドット記法」で軽く触れましたが、すでに Toil では `util.double(3)` のようなモジュール風の書き方ができるようになっています。でも、ファイルから読まないとモジュールっぽくない気がするかもしれません。やりましょう。

組み込み関数を追加します。

```diff py
 class Interpreter:
     ...

     def _builtins(self):
         ...

         self._env.define(Ident("print"), lambda args: print(*args))

+        def _load(path):
+            with open(path, "r") as f: src = f.read()
+            return Evaluator().eval(self.ast(src), Environment(self._env))
+        self._env.define(Ident("load"), lambda args: _load(args[0]))

         self._env = Environment(self._env)
 
     def stdlib(self) -> None:
         ...
```

`with open(path, "r") as f: src = f.read()` は `path` で示されるファイルの内容をまるごと `src` に読み込みます。`with` は文なので `lambda` の中に書けないため、いったん `_load()` という別関数を定義してから `lambda` で呼んでいます。

ソースが読み込めてしまえばあとはいつもどおり AST にして評価してやればいいのですが、`Environment(self._env)` と環境を 1 段深くしていることに注意してください。`self._env` をそのまま `eval()` に渡してしまうと読み込んだ Toil ソースコード内の変数・関数がそのまま呼び出し元の環境に定義されてしまい、もし同名の変数があれば上書きされてしまうことになります。

また、`eval()` の戻り値を `return` で返しているのも地味ながら大事なところです。モジュールは以下のような形で作り、最後にモジュールの外に見せたい関数を辞書に入れて返します。Python はモジュール外に公開する変数や関数を明示的に指定する機能を持ちませんが[^underscore-and-all]、JavaScript 等ではエクスポート（export）機能にあたります[^commonjs-export]。

[^underscore-and-all]: 名前の先頭に `_` をつけるのはただの慣習で、つけたからといってアクセスできなくなるわけではありません。アクセスしないでね、とお願いしているだけです。また、`__all__` というリストを定義することで `from util import *` で読み込まれる名前を制限することはできますが、`util._two()` のように書けばアクセスできてしまいます。

[^commonjs-export]: しくみとしては CommonJS で `module.exports = { double, half }` と書くのに似ています。戻り値にしている分 Toil の方がキレイなやり方になってるんじゃないかな・・・[^lua-export]？ES Modules で `export { double, half }` と書くのは宣言なのでちょっと雰囲気が違います（中でどう動いて公開したり隠しているかは未調査です）。

[^lua-export]: Lua 言語で `return { double = double, half = half }` と書くのはしくみ的にはまったく同じですが、Toil の方が短く書けます！

```txt:util.toil
def double(a) do a * _two() end;
def half(a) do a / _two() end;

def _two() do 2 end;

{double, half}
```

（`util.toil` は `toil.py` 実行時のカレントディレクトリ（おそらく同じディレクトリ）に作成してください）

`load()` でこのモジュールを読み込んだ時に `{double, half}` が返され、読んだ側からするとエクスポートされたことになります。`_two()` はエクスポートされず、モジュールの外部からはアクセスできない関数になります。

```py
    # Example

    print("Module:")

    toil.walk(r""" util := load('util.toil') """)
    print(toil.walk(r""" util.double(2) """)) # -> 4
    print(toil.walk(r""" util.half(2) """)) # -> 1
    # print(toil.walk(r""" double(2) """)) # -> Undefined variable
    # print(toil.walk(r""" util._two() """)) # -> Undefined variable
```

モジュールっぽく使えています。`import util` のような読み込み方に当たります。隠ぺいもちゃんと働いていて、`double(2)` や `util._two()` が呼べないようになっています。

```py
    toil.walk(r""" {double, half} := load('util.toil') """)
    print(toil.walk(r""" double(4) """)) # -> 8
    print(toil.walk(r""" half(4) """)) # -> 2
```

こちらは `from util import double, half` に相当する読み込み方。

```py
    toil.walk(r""" {double} := load('util.toil') """)
    print(toil.walk(r""" double(6) """)) # -> 12
```

エクスポートされているものをすべて読み込む必要はありません。辞書パターンで余りが出ても気にしないことにしたからですね。

```py
    toil.walk(r""" {double: dbl} := load('util.toil') """)
    print(toil.walk(r""" dbl(8) """)) # -> 16
```

`from util import double as dbl` のようなことがしたければこれで。

ファイルから読み込む機能を付けただけで、あとは辞書のパターンマッチに任せたらインポートでやりたいことがほとんど[^from-util-import-star]できてしまいました。構文糖衣を作ればもうすこし言語の機能っぽい見かけにもできますがここまでにしておきます。

[^from-util-import-star]: `from util import *` 的なことだけできません。辞書の rest パターンを拡張すればできるかな・・・？

パターンマッチを生かした拡張を続けます。

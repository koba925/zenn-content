title: "6.3 match 式"
---

ではいよいよ match 式を実装します。こういう風に書けるようにします。

```
match [2, 3]
    case [a, b] then 
        a * b
    case _ then
        "no"
end
```

この場合、`[2, 3]` が `[a, b]` とマッチするので `a * b` つまり `6` が値になります。マッチしなければ `"no"` になります。

## 前準備

match 式そのものを実装する前に前準備があります。

今まで、`bind()` ではパターンと値がマッチしなかったときエラーを出して終了していましたが、match 式でパターンにマッチしなかったからと言ってプログラムが終了してしまっては困ります。

今まで `bind()` は `None` を返していましたが、マッチに成功したら `True`、失敗したら `False` を返していずれも実行を継続します。

```diff py
 class Environment:
     ...

-    def bind(self, pattern: Expr, value: Value) -> None:
+    def bind(self, pattern: Expr, value: Value) -> bool:
         match pattern:
-            case Ident() as ident: self.define(ident, value)
+            case Ident() as ident:
+                self.define(ident, value)
+                return True
             case list():
-                assert isinstance(value, list), \
-                    f"Pattern mismatch @ bind(): {pattern}"
-                self._bind_list(pattern, value)
+                return isinstance(value, list) and self._bind_list(pattern, value)
-            case unexpected:
-                assert False, f"Unexpected pattern @ bind(): {unexpected}"
+            case _:
+                return False
 
     def _bind_list(self, pattern, value):
-        assert len(pattern) == len(value), \
-            f"Item counts mismatch @ _bind_list(): {pattern} {value}"
```

呼び出し側で `False` が返ってきたらエラーにするようにします。

副作用で、`bind()` が失敗したときのエラーメッセージが失敗の原因によらず `Pattern mismatch` というメッセージになってしまいました。`bind()` が `True`/`False` だけではなくエラーの原因を返すとか、あるいはエラーに応じた例外を返すなどすればこれまで同様に原因に応じたエラーメッセージにすることもできますがここではそこまでがんばらないことにしました。

ちゃんと動くか試しておきます。

```py
    print("Parameter match:")

        a := []; for [i, j] in [[2, 3], [4, 5]] do a.push([i, j]) then a end

    # toil.walk(r""" for [i, j] in [2, 3] do None end """) # -> Pattern mismatch
```

大丈夫そうです。

## match 式

今度こそ match 式を実装しましょう。

```diff py
 class Parser:
     ...

     def _primary(self) -> Expr:
         match self._current_token():
             ...
             case Ident("if"): return self._if()
+            case Ident("match"): return self._match()
             case Ident("while"): return self._while()
             ...

     ...
 
     def _if(self):
         ...
 
+    def _match(self):
+        self._current_and_advance()
+        val_expr = self._expression()
+        cases = []
+        while self._current_token() == Ident("case"):
+            self._current_and_advance()
+            pat_expr = self._expression()
+            self._consume(Ident("then"))
+            body_expr = self._expression()
+            cases.append((pat_expr, body_expr))
+        self._consume(Ident("end"))
+        return (Ident("match"), [val_expr, cases])

     def _while(self):
         ...
```
`match` と値の式を読んだら、`case` が出てくる間 case 節を読んでいきます。case 節は数が決まっていないので、`(<パターン>, <case本体>)` というペアを配列に追加していきます。`end` で終わって `(match, [<値>, [<case節>, <case節>, ...]])` という AST を返します。

`Evaluator` の方はもっと単純で、

```diff py
 class Evaluator:
     def eval(self, expr: Expr, env: Environment) -> Value:
         match expr:
             ...
             case (Ident("or"), [left_expr, right_expr]):
                 return self.eval(left_expr, env) or self.eval(right_expr, env)
+            case (Ident("match"), [val_expr, cases]):
+                return self._match(val_expr, cases, env)
             case (Ident("while"), [cond_expr, body_expr, then_expr, else_expr]):
                 return self._while(cond_expr, body_expr, then_expr, else_expr, env)
             ...

     ...

     def _if(self, cond_expr, then_expr, else_expr, env):
         ...

+    def _match(self, val_expr, cases, env):
+        val = self.eval(val_expr, env)
+        for pat_expr, body_expr in cases:
+            if env.bind(pat_expr, val):
+                return self.eval(body_expr, env)
+        return None

     def _while(self, cond_expr, body_expr, then_expr, else_expr, env):
         ...
```

値を評価したら case 節をひとつずつ見ながら、もしパターンがマッチしたら case 本体を評価してその値を返します。ひとつもマッチしなければ `None` を返します。

使ってみましょう。

```py
    print("Match:")

    print(toil.ast(r"""
        match [2, 3] case [a, b] then a * b case _ then "no" end
    """)) # -> (match, [[2, 3], [([a, b], (mul, [a, b])), (_, 'no')]])
```

いつもより複雑な AST なので、思っていた通りか見ておいてください。

```py
    print(toil.walk(r"""
        match [2, 3] case [a, b] then a * b case _ then "no" end
    """)) # -> 6
    print(toil.walk(r""" [a, b] """)) # -> [2, 3]
```

動きました。match 式のパターンに合致した変数は match 式の外に出ても残ったままです。これは保守性の高いプログラムを書くには不都合な点もありますが、処理系をシンプルに保つため Toil 全体のポリシーとしています。if 式の中で定義した変数や for 式のループ変数も同様に式から出ても残ります。変数のスコープを最小限にとどめることも大事ですが、一貫性も大事な要素だと考えています。この構文は変数が外に漏れる、この構文は漏れない・・・などとブレがあると認知負荷が上がります。

```py
    print(toil.walk(r"""
        match [4, 5] case [a, [b, c]] then a * b case _ then "no" end
    """)) # -> no
```

最初のケースでマッチしなければ次に進むこと、`_` には何でもマッチすること（普通の変数でも同様）が確認されました。

```py
    print(toil.walk(r""" [a, b, _] """)) # -> [4, 3, [4, 5]]
```

変数のマッチが途中で失敗した場合も、マッチしたところまでは変数の値が残っています。

```py
    print(toil.walk(r""" match 2 case [a, b] then a * b end """)) # -> None
    print(toil.walk(r""" match 2 end """)) # -> None
```

どのケースにもマッチしなかった場合や、そもそもケースが存在しない場合は `None` を返します。エラーにはなりません。


構文エラーのチェック。

ちょっと難しそうな match 式ですが、順を追って実装すれば意外と作れるものだな、とわかっていただけたと思います。どちらかというと仕様をどうするべきか悩む感じです。

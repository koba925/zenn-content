この節ではアロー関数を導入します。`func a, b do a + b end` の代わりに `[a, b] -> a + b` と書けるというものです。見た目が変わるだけですが直観的で JavaScript をはじめ複数の言語で採用されています。仮引数は配列に入れるのを基本としますが、仮引数が 1 個のときは配列に入れなくてもいいものとします。`[a] -> a + 1` と書く代わりに `a -> a + 1` と書けるということです。こうなるとさらに直観的に読むことができます。

`[a, b] -> a + b` というのは一見特殊な形に見えるかもしれませんが、形だけ見れば左辺が配列で演算子が `->` という二項演算子で表された式にすぎません。

まずは `Scanner` で `->` をトークンとして認識するようにします。

```diff py

     ...
```

2 文字のトークンを認識する処理は `==` などと同様なので `_two_char_operator()` という関数に切り出して 2 か所で共有しました。今は 2 文字目が `=` や `>` と 1 種類ずつしかありませんが、後ほど複数の文字が続く場合が出てきますのでちょっと先回りで複数文字を指定できるようにしています。

`->` の優先度は `:=` や `=` と `and`・`or` の間とします。そのあたりがちょうどよさそう。右結合の二項演算子なのですが、ちょっとだけ特殊なことをしたいので `_binary_right()` は使いません。

```diff py

     ...

             Ident(":="): Ident("define"), Ident("="): Ident("assign")
-        }, self._and_or)

+        if self._current_token() == Ident("->"):
+            self._current_and_advance()
+            body_expr = self._arrow()
+            params = left if isinstance(left, list) else [left]
+            return (Ident("func"), [params, body_expr])
+        return left

```

特殊なところというのは `params = left if isinstance(left, list) else [left]` で、左辺が配列でないときは配列に入れてあげます。これにより `a -> a + 1` が AST では `[a] -> a + 1` と同じになります。

`(Ident("func"), [params, body_expr])` という AST はこれまでの関数と全く同じ形なので `Evaluator` に手を入れる必要はありません。

実行例です。

```py
    # Example

    print("Arrow function:")

    print(toil.ast(r""" [a, b] -> a + b """))
    # -> (func, [[a, b], (add, [a, b])])
    print(toil.ast(r""" func a, b do a + b end """))
    # -> (func, [[a, b], (add, [a, b])])
```

アロー関数も `func` で書いた関数も AST は同じ。

```py
    print(toil.walk(r""" ([a, b] -> a + b)(2, 3) """)) # -> 5
    # toil.walk(r""" ([a, b] -> a + b)(2) """) # -> Pattern mismatch
```

なので当然同じように動きます。左辺はパターンなので引数の形が合わなければ `Pattern mismatch` のエラーになります。`->` は関数呼び出し `()` より優先度が低いため、アロー関数をその場で呼び出すときは `([a, b] -> a + b)(2, 3)` のようにカッコで囲みます。

```py
    print(toil.walk(r""" myadd := [a, b] -> a + b; myadd(2, 3) """)) # -> 5
```

変数に覚えさせてももちろん使えます。

```py
    print(toil.walk(r""" ([] -> 2)() """)) # -> 2
    print(toil.walk(r""" ([a] -> a + 2)(3) """)) # -> 5
```

引数の数が 0 個・1 個でも問題なし。

```py
    print(toil.walk(r""" (a -> a + 2)(3) """)) # -> 5
```

引数が 1 個のときは配列の形にしなくても大丈夫。

```py
    print(toil.walk(r""" ({a, b} -> a + b)({a: 2, b: 3}) """)) # -> 5
    # toil.walk(r""" ({a} -> a + 2)({b: 3}) """) # -> Pattern mismatch
```

これも引数が 1 個のうちに入ります。

```py
    print(toil.walk(r""" ([[a, b]] -> a + b)([2, 3]) """)) # -> 5
```

ただし、1 個の配列を受けとるときは残念ながら外側の `[]` が必須です。見分けがつかないので。すっきりした解決策は思いつきませんでした。今の Toil の文法とは相性がよくないですが、パターンマッチを使うこと前提で、関数は引数を 1 個しかとらない（複数の引数を渡したければ配列に入れて渡す）という約束で構文を考えてみるのも面白いかもしれません。

```py
    print(toil.walk(r""" ([a, *b] -> b)(2, 3, 4) """)) # -> [3, 4]
    print(toil.walk(r""" (int(a) -> a + 2)(3) """)) # -> 5
    # toil.walk(r""" (int(a) -> a + 2)('aaa') """) # -> Pattern mismatch
```

ほかにも好きなパターンを使えます。

```py
    print(toil.ast(r""" f := a -> a or 2 """))
    # -> (define, [f, (func, [[a], (or, [a, 2])])])
    print(toil.walk(r""" f := a -> a or 2; f(False) """)) # -> 2
```

優先度の確認。

```py
    print(toil.ast(r""" a -> b -> a + b """))
    # -> (func, [[a], (func, [[b], (add, [a, b])])])
    print(toil.walk(r""" (a -> b -> a + b)(2)(3) """)) # -> 5
```

右結合の確認。

```py
    toil.walk(r"""
        def quicksort(a) do
            if a.len() <= 1 then a else
                [pivot, *rem] := a;
                # left := rem.filter(func x do x < pivot end);
                left := rem.filter(x -> x < pivot);
                # right := rem.filter(func x do x >= pivot end);
                right := rem.filter(x -> x >= pivot);
                quicksort(left) + [pivot] + quicksort(right)
            end
        end
    """)
    print(toil.walk(r""" quicksort([5, 3, 8, 4, 2]) """)) # -> [2, 3, 4, 5, 8]
```

`quicksort()` で関数を渡すところがすっきり書けるようになりました。構文で見かけを変えただけですがけっこう違って見えますね。

ところで。

パターンマッチ生かしてアロー関数作りました！みたいな顔して書いていますが実はアロー関数の実装にパターンマッチが必須というわけではありません。第 4 章で配列が使えるようになったあとなら同じようにしていつでも導入することはできたんですが、「基本のインタプリタ」に入るものではない気がしたのと、パターンマッチと組み合わさると面白いところではあるのでここに持ってきました。なんで今？と思った方もいるかもしれないのでちょっとおことわり。

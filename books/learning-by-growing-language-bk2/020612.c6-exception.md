第 6 章最後の題材は例外です。Python の try 文と類似した try 式を作ります。

try 式は以下のように書くことにします。例外のための型はとくに設けずパターンで分けます。`except <例外パターン> then <例外ハンドラ>` を except 節と呼ぶことにします。

```
try <本体>
except <例外パターン> then <例外ハンドラ>
except <例外パターン> then <例外ハンドラ>
...
end
```

`raise(<値>)` で例外を送出します。こんな感じに組み合わせて使うイメージです。

```
try
    ...
    if ... then raise(['FooException', 2]) end
    ...
except ['FooException', val] then recover_foo(val)
except ['BarException', val] then recover_bar(val)
end
```

`Parser` に `try` の構文を追加します。

```diff py
 class Parser:
     ...
 
     def _primary(self) -> Expr:
         match self._current_token():
             ...
             case Ident("for"): return self._for()
+            case Ident("try"): return self._try()
             case Ident("defclass"): return self._defclass()
             ...

     ...

     def _for(self):
         ...
 
+    def _try(self):
+        self._current_and_advance()
+        body_expr = self._expression()
+        clauses = []
+        while self._current_token() == Ident("except"):
+            self._current_and_advance()
+            exc_pat = self._expression()
+            self._consume(Ident("then"))
+            exc_expr = self._expression()
+            clauses.append((exc_pat, exc_expr))
+        self._consume(Ident("end"))
+        return (Ident("try"), [body_expr, clauses])

     def _defclass(self):
         ...
```

except 節は複数書けますのでループで回して `clauses` に溜めてから AST に入れています。

例外を処理するには、いくつもの関数呼び出しを遡って `try ... except` に戻る必要があります。`return` や `break` などと同様に（Python の）例外を使います。これまでも Toil の `if`・`while` の実装に Python の `if`・`while` を使った箇所がありましたが、Toil の例外を処理するのに Python の例外のしくみを使うのはちょっと面白いですね。これが唯一の実現方式というわけではありませんが。例外処理と `return` や `break` が混在してもきちんと動くかどうかはちょっと気になるので実行例のところでいろいろ試してみましょう。

```diff py
+class ToilException(Exception):
+    def __init__(self, val: Value = None) -> None: self.val = val

 class ReturnException(Exception):
     def __init__(self, val: Value = None) -> None: self.val = val
```

例外には値を覚えておくだけです。

```diff py
 class Evaluator:
     def eval(self, expr: Expr, env: Environment) -> Value:
         match expr:
             ...
             case (Ident("for"), [pat_expr, coll_expr, body_expr, then_expr, else_expr]):
                 return self._for(
                     pat_expr, coll_expr, body_expr, then_expr, else_expr, env
                 )
+            case (Ident("try"), [body_expr, clauses]):
+                return self._try(body_expr, clauses, env)
+            case (Ident("raise"), args):
+                raise ToilException(self.eval(args[0], env))
             case (Ident("dot"), [target_expr, attr_name]):
                 return self._dot(target_expr, attr_name, env)
             ...

     ...

     def _for(self, pat_expr, coll_expr, body_expr, then_expr, else_expr, env):
         ...
 
+    def _try(self, body_expr, clauses, env):
+        try:
+            return self.eval(body_expr, env)
+        except ToilException as e:
+            for exc_pat, exc_expr in clauses:
+                if env.bind(exc_pat, e.val):
+                    return self.eval(exc_expr, env)
+            raise e

     def _dot(self, target_expr, attr_name, env):
         ...
```

先に `raise` から済ませておくと、1 つめの引数を評価してそれを例外の値として `ToilException` を発生させているだけです。

`try` が来たら、まず本体を評価します。本体評価中に例外が発生したら except 節の処理に入り、`clauses` に保存された例外パターンと例外ハンドラのペアを 1 つずつ見ていって、例外パターンが例外の値とマッチすれば例外ハンドラを評価しています。どの例外パターンにも合致しなければそのまま元の例外を送りなおします。

最後に `Interpreter` クラスの修正です。

```diff py
 class Interpreter:
     ...

     def eval(self, expr: Expr) -> Value:
         try:
             return Evaluator().eval(expr, self._env)
+        except ToilException as e:
+            assert False, f"Unhandled exception @ eval(): {e.val}"
         except ReturnException as e: return e.val
         except ContinueException: assert False, "Continue at top level @ eval()"
         except BreakException: assert False, "Break at top level @ eval()"

     ...
```

`raise` した例外が `try` で捕まえられずに最上位まで戻ってきてしまったときにエラーを出して終わるようにしています。

実行例です。

```py
    # Example

    print("Exception:")

    print(toil.ast(r"""
        try raise('Foo') except 'Foo' then 'foo' except 'Bar' then 'bar' end
    """)) # -> (try, [(raise, ['Foo']), [('Foo', 'foo'), ('Bar', 'bar')]])
```

AST の形（特に `clauses` で例外パターンと例外ハンドラのペアが並んでいるところ）や `raise` の形（普通の関数呼び出しの形）を見ておいてください。

```py
    print(toil.walk(r"""
        try 2
        except ['FooException', val] then ['foo', val]
        except ['BarException', val] then ['bar', val]
        end
    """)) # -> 2
```

try 式の本体を実行中に例外が発生しなければ、本体の値が try 式の値になります。

```py
    print(toil.walk(r"""
        try 2; raise(['FooException', 2]); 1 / 0
        except ['FooException', val] then ['foo', val]
        except ['BarException', val] then ['bar', val]
        end
    """)) # -> ['foo', 2]

    print(toil.walk(r"""
        try 2; raise(['BarException', 3]); 1 / 0
        except ['FooException', val] then ['foo', val]
        except ['BarException', val] then ['bar', val]
        end
    """)) # -> ['bar', 3]
```

`raise` によって例外が発生すると、本体の評価はそこで終わって except 節を見ていき、例外にマッチした例外パターンに対応する例外ハンドラを評価して、その値を try 式全体の値とします。

`1 / 0` は「ここには到達しませんよ」というマーク代わりに書いています。もしここに到達してしまったら Division by Zero のエラー（Python 側の例外）で止まってしまうのでわかります。

```py
    print(toil.walk(r"""
        try
            try raise(['BarException', 3])
            except ['FooException', val] then ['foo', val]
            end;
            1 / 0
        except ['BarException', val] then ['bar', val]
        end
    """)) # -> ['bar', 3]
```

マッチする例外パターンがなければあらためて元の例外が発生し、外側の try 式に処理が渡されます。

```py
    # toil.walk(r"""
    #     try 2; raise(['BarException', 3]); 1 / 0
    #     except ['FooException', val] then ['foo', val]
    #     end
    # """) # -> Unhandled exception
```

どの try 式にもマッチしなければ `Unhandled exception` のエラーになります。

while 式や `break` との組み合わせを見ていきます。

```py
    print(toil.walk(r"""
        a := 0; while a < 5 do
            try a = a + 1; if a == 3 then break end
            except _ then 1 / 0 end
        then 1 / 0 else a end
    """)) # -> 3
```

try 式のなかから `break` できました。

```py
    print(toil.walk(r"""
        try
            a := 0; while a < 5 do
                a = a + 1; if a == 3 then raise(4) end
            then 1 / 0 else 1 / 0 end
        except e then e end
    """)) # -> 4
```

while 式の中で `raise` しても while 式の外の try 式までちゃんと例外が伝わります。

次は関数や `return` との組み合わせです。

```py
    print(toil.walk(r"""
        func do
            try return(2) except _ then 3 end;
            4
        end ()
    """)) # -> 2

    print(toil.walk(r"""
        func do
            try raise(2) except e then return(e + 1) end;
            4
        end ()
    """)) # -> 3
```

try 式の本体・例外ハンドラからでも普通に `return` できています。

```py
    print(toil.walk(r"""
        def risky_func() do raise(2) end;

        try risky_func()
        except e then e + 1
        end
    """)) # -> 3
```

関数の中で `raise` すると、関数の外まで例外が伝わります。

```py
    print(toil.walk(r""" try 2 end """)) # -> 2
```

except 節が 0 個でも合法。

```py
    # toil.walk(r""" try 2 except e 3 end """) # -> Expected then
    # toil.walk(r""" try 2 except e then 3 """) # -> Expected end
```

## 第 6 章のまとめ

パターンマッチ、どうだったでしょうか。以下のように様々な箇所でパターンマッチが使えるようになりました。

* モジュール読み込み

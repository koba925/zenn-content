次は型パターンを作ります。`match x case int(n) then ... end` と書けば `x` が `int` だったときに `n` に `x` が入り、`then` 以下が実行されるようにします。

```diff py
 class Environment:
     ...

     def bind(self, pattern: Expr, value: Value) -> bool:
         match pattern:
             ...
             case (Ident("tuple"), sub_pats):
                 return isinstance(value, tuple) and self._bind_seq(sub_pats, value)
+            case (Ident(typ), [val_pat]):
+                return type(value).__name__ == typ and self.bind(val_pat, value)
             case _:
                 return type(pattern) is type(value) and pattern == value
```

`int(n)` のような形は構文解析では関数呼び出しとして扱われるので `case (Ident(typ), [val_pat])` で型の部分とカッコ内に書かれたパターン（普通は変数を書きますがパターンも許します）を取り出した後、型が合っていることを確認してからパターンと値をマッチさせます。Python の `type(value).__name__` で値の型名の文字列（`2` なら `"int"`、`False` なら `"bool"`）が取れるので、それが `typ` と一致するか確認しています。

お気づきになったかもしれませんが、タプルだけは型パターンが使えません。`tuple(t)` という形はすでにタプルパターンで使っているからです。配列リテラル（`[...]`）や辞書リテラル（`{...}`）のようにタプルもリテラル表記があればタプルパターンでリテラルの形を使い、`tuple(t)` の形は型パターン向けに取っておけたんですけれども。とはいえ `case tuple(*t)` と書けば同じことができるので困ることはありません。言語仕様に対称性をどれだけ求めるかという話ですね。

あと、`int()` のようにカッコ内になにも書かない形はサポートしていません。`case (Ident(typ), []):` というケースを付け足すだけで対応できるのですが、`int(_)` などと書けばよいので省いています。

実行例です。

```py
    # Example

    print("Type pattern:")

    print("Match:")

    print(toil.ast(r""" match x case bool(b) then 'bool' end """))
    # -> (match, [x, [((bool, [b]), 'bool')]])
```

`bool(b)` は見た目の通り関数呼び出しとして AST に変換されています。

```py
    toil.walk(r"""
        def foo(x) do
            match x
                case bool(b) then ['bool', b]
                case int(n) then ['int', n]
                case str(s) then ['str', s]
                case list(l) then ['list', l]
                case dict(d) then ['dict', d]
                case _ then ['else', x]
            end
        end
    """)

    print(toil.walk(r""" foo(False) """)) # -> ['bool', False]
    print(toil.walk(r""" foo(2) """)) # -> ['int', 2]
    print(toil.walk(r""" foo('hello') """)) # -> ['str', 'hello']
    print(toil.walk(r""" foo([2]) """)) # -> ['list', [2]]
    print(toil.walk(r""" foo({a: 2}) """)) # -> ['dict', {'a': 2}]
    print(toil.walk(r""" foo(tuple(2)) """)) # -> ['else', (2,)]
```

タプル以外の型はすべて型パターンで判別できます。

```py
    print("Parameter match:")

    toil.walk(r""" def foo(int(n)) do n end """)
    print(toil.walk(r""" foo(2) """)) # -> 2
    # print(toil.walk(r""" foo(True) """)) # -> Pattern mismatch

    print("Destructuring bind:")

    print(toil.walk(r""" int(n) := 2; n """)) # -> 2
    # print(toil.walk(r""" int(n) := True; n """)) # -> Pattern mismatch
```

型が合わないとエラーで止まってしまうのであまり実用的ではないかもしれませんが関数呼び出しや分割代入でも型パターンは動きます。

```py
    # print(toil.walk(r""" int(2) := 3 """)) # -> Pattern mismatch
    print(toil.walk(r""" list([a, b]) := [2, 3]; [a, b] """)) # -> [2, 3]
    # print(toil.walk(r""" list([a, b]) := [2] """)) # -> Pattern mismatch
```

型パターンのカッコの中はパターンとして扱いますので変なものが入ってると `Pattern mismatch` になりますし、マッチするならパターンを書いてもかまいません。ただ `[a, b]` と書くだけで配列であることも確認されますので `list([a, b])` というパターンは書けても意味はありません。`list(l)` のように変数を書くなら（同じことをする）`[*l]` より意図が分かりやすくて意味がありますが、`list([a, b])` のように中身までパターンで書くならただの `[a, b]` で十分ですね。

型のチェックと `bind()` の再帰呼び出しだけで型パターンも簡単に拡張することができました。

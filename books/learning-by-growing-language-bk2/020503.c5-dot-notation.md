辞書の要素へのアクセスは `d["a"]` のように書いて、これはこれでいいんですけれども JavaScript も書くひとはちょっとまどろっこしく感じるでしょう。`d.a` って書きたい！と。私もそう思います。やりましょう。

`.` をトークンとして扱います。

```diff py
 class Scanner:
     ...
 
     def tokenize(self) -> list[Token]:
         while (c := self._current_char()) != "$EOF":
             self._start_pos = self._current_pos
             match c:
                 ...
-                case c if c in "+-*/%()[]{},;":
+                case c if c in "+-*/%()[]{}.,;":
                     self._tokens.append(Ident(c)); self._advance()
                 ...
```

`.` は左結合で関数呼び出し（`()`）やインデックス表記（`[]`）と同じ優先度を持つことにします。
`a[i].f(x)` などと連続して書いたときに左から順番に読んでいくようにするためです。

ドット記法専用に `dot` という AST を使います。ただ辞書にアクセスするだけなら `index` に変換してもいいんですが、これからいろいろドット記法に意味を重ねていくからです[^design-perspective]。

[^design-perspective]: 言語設計的には 1 つの記号にいくつも意味を持たせるのは混乱を招きそうであまり推奨されないかもしれません。処理系もその分複雑になりますし。

```diff py
 class Parser:
     ...
 
     def _unaries(self):
-        return self._unary({Ident("-"): Ident("neg")}, self._call_index)
+        return self._unary({Ident("-"): Ident("neg")}, self._call_index_dot)
 
-    def _call_index(self):
+    def _call_index_dot(self):
         target = self._primary()
-        while (op := self._current_token()) in (Ident("("), Ident("[")):
+        while (op := self._current_token()) in (
+            Ident("("), Ident("["), Ident(".")
+        ):
             self._current_and_advance()
             match op:
                 case Ident("("):
                     ...
                 case Ident("["):
                     ...
+                case Ident("."):
+                    attr_name = self._current_and_advance()
+                    assert type(attr_name) is Ident and is_ident(attr_name.name), \
+                        f"Invalid attribute @ _call_index_dot(): {attr_name}"
+                    target = (Ident("dot"), [target, attr_name.name])
         return target
 
     def _primary(self) -> Expr:
         ...
```

`attr_name` は `Ident` 型ですが、辞書のキーは `str` を想定しているので `attr_name.name` で文字列を取り出しています。

`Evaluator` に `dot` の処理を追加します。

```diff py
 class Evaluator:
     def eval(self, expr: Expr, env: Environment) -> Value:
         match expr:
             ...
             case (Ident("for"), [var_expr, coll_expr, body_expr, then_expr, else_expr]):
                 ...
+            case (Ident("dot"), [target_expr, attr_name]):
+                return self._dot(target_expr, attr_name, env)
             case (op_expr, args_expr):
                 return self._op(op_expr, args_expr, env)
             ...

     ...

     def _for(self, var_expr, coll_expr, body_expr, then_expr, else_expr, env):
         ...
 
+    def _dot(self, target_expr, attr_name, env):
+        target_val = self.eval(target_expr, env)
+        assert isinstance(target_val, dict), \
+            f"Invalid dot target @ _dot(): {target_val}"
+        return target_val[attr_name]

     def _op(self, op_expr, args_expr, env) -> Value:
         ...
```

たいしたことはしていません。`dot` だったら辞書の要素を返すだけですね。

おっと代入の修正を忘れてはいけません。といっても `dot` も許す、だけです。説明が後になりましたが `_assign()` はさっき出てきた `_dot()` よりも上に定義されていますのでご注意を。

```diff py
     ...

     def _assign(self, left_expr, right_expr, env):
         val = self.eval(right_expr, env)
         match left_expr:
             case Ident() as ident:
                 return env.assign(ident, val)
-            case (Ident("index"), [coll_expr, index_expr]):
+            case (Ident("index"), [coll_expr, index_expr]) | \
+                 (Ident("dot"), [coll_expr, index_expr]):
                 coll_val = self.eval(coll_expr, env)
                 index_val = self.eval(index_expr, env)
                 match coll_val:
                     case list() if isinstance(index_val, int):
                         coll_val[index_val] = val
                     case dict() if isinstance(index_val, str):
                         coll_val[index_val] = val
                     case _: assert False, \
-                        f"Invalid index assignment @ _assign(): {left_expr}"
+                        f"Invalid index/dot assignment @ _assign(): {left_expr}"
                 return val
             case unexpected:
                 assert False, f"Invalid assign target @ _assign(): {unexpected}"

     ...
```

`d.a = ...` という式を評価するとき、`case` の `(Ident("dot"), [coll_expr, index_expr])` で `index_expr` として取り出されるのは `Ident("a")` ではなく `attr_name.name` つまり `"a"` という文字列です。文字列は `index_val = self.eval(index_expr, env)` と評価してもやはり文字列のままなので、`index` のときと全く同じように `coll_val[index_val]` で辞書の要素にアクセスできます。

実行例です。

```py
    # Example

    print("Dot notation:")

    toil.walk(r""" d := {"a": 2, "b": 3} """)
    print(toil.ast(r""" d.a """)) # -> (dot, [d, 'a'])
    print(toil.walk(r""" d.a """)) # -> 2
```

ドット記法で辞書の要素にアクセスできました。AST でキーが文字列になっているのも見えます。

```py
    toil.walk(r""" d.a = 4; d.c = {e: 5} """)
    print(toil.walk(r""" d """)) # -> {'a': 4, 'b': 3, 'c': {'e': 5}}
    print(toil.walk(r""" d.c.e """)) # -> 5
    toil.walk(r""" d.c.e = 6 """)
    print(toil.walk(r""" d """)) # -> {'a': 4, 'b': 3, 'c': {'e': 6}}
```

辞書要素への代入や入れ子になった辞書の要素へのアクセスも大丈夫です。`d.c.e = 6` の動きはかなりややこしくなりますが AST を表示して丁寧に処理を追ってみてください。再帰ってスゴイ！

こんな風に辞書の要素に関数を割り当てると、Python でモジュールをインポートしたような書き方（`math.sin()` のような）ができます。

```py
    toil.walk(r"""
        util := {
            double: func a do a * 2 end,
            half: func a do a / 2 end
        }
    """)
    print(toil.ast(r""" util.double(3) """)) # -> ((dot, [util, 'double']), [3])
    print(toil.walk(r""" util.double(3) """)) # -> 6
    print(toil.walk(r""" util.half(6) """)) # -> 3
```

関数呼び出し `(<関数を表す式>, [<引数>, ...])` の `<関数を表す式>` の部分が `(dot, [util, 'double'])` になっており、`_op()` でそれが評価されて関数が取り出されるからですね。`u := util` とすれば `import util as u` のような、`dbl := util.double` とすれば `from util import double as dbl` のような意味になります。内部を隠ぺいする機能はありませんけれども。

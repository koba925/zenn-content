title: "6.6 タプルパターン"
---

この節ではタプルにマッチするパターンを作ります。Python では配列とタプルを区別せずにマッチしますが、Toil では配列パターンは配列のみ、タプルパターンはタプルのみにマッチするようにします。

書き方はちょっと長たらしいですがタプルの値を書く時のそのままの形を使い、`match val case tuple(a, b) then a + b end` のように書くことにします。これなら字句解析・構文解析に変更は要りません。

例によって `bind()` に手を入れます。

```diff py
 class Environment:
     ...

     def bind(self, pattern: Expr, value: Value) -> bool:
         match pattern:
             case Ident() as ident:
                 self.define(ident, value)
                 return True
             case list():
-                return isinstance(value, list) and self._bind_list(pattern, value)
+                return isinstance(value, list) and self._bind_seq(pattern, value)
+            case (Ident("tuple"), sub_pats):
+                return isinstance(value, tuple) and self._bind_seq(sub_pats, value)
             case _:
                 return type(pattern) is type(value) and pattern == value
 
-    def _bind_list(self, pattern, value):
+    def _bind_seq(self, pattern, value):
         for i, sub_pat in enumerate(pattern):
             match sub_pat:
                 case (Ident("*"), [rest_pat]):
                     return i == len(pattern) - 1 and self.bind(rest_pat, value[i:])
                 case _:
                     if i >= len(value) or not self.bind(sub_pat, value[i]):
                         return False
         return len(pattern) == len(value)
```

タプルはほとんど配列と同様に扱えるので `_bind_list()` の名前を変えて `_bind_seq()` とし、配列でもタプルでも呼び出して同じように処理させています。

そもそも Toil でタプルを作る `tuple(...)` は特別な構文ではなく、ただの組み込み関数の呼び出しでした。そのため、パターンとして `tuple(a, b)` と書いた場合も、構文木（AST）は関数呼び出しと同じ `(Ident("tuple"), sub_pats)` という形になります。

`bind()` ではこの構文木を関数として評価するのではなく、タプルパターン（`case (Ident("tuple"), sub_pats)`）として受け取ります。引数部分の `sub_pats` が要素パターンの配列になっているので、それをそのまま `_bind_seq()` に渡してやるだけで要素ごとのマッチが行われます。

ではやってみましょう。まずは AST の形を確認しておきます。

```py
    # Example

    print("Parameter match:")

    print(toil.ast(r""" def foo(a, tuple(b, c)) do print(a, b, c) end """))
    # -> (define, [foo, (func, [[a, (tuple, [b, c])], (print, [a, b, c])])])
```

仮引数のタプルの部分が `(tuple, [b, c])` と、関数呼び出しの形になっているのがわかります。では実際に動かしてみましょう。

```py
    toil.walk(r""" def foo(a, tuple(b, c)) do print(a, b, c) end """)
    toil.walk(r""" foo(2, tuple(3, 4)) """) # -> 2 3 4
```

できてますね。

```py
    # toil.walk(r""" foo(2, [3, 4]) """) # -> Pattern mismatch
    # toil.walk(r""" foo(2) """) # -> Pattern mismatch
```

タプルパターンに配列をマッチさせようとするとエラーになります。これは Python との相違点です。

```py
    # toil.walk(r""" def foo(a, [b, c]) do print(a, b, c) end """)
    # toil.walk(r""" foo(2, tuple(3, 4)) """) # -> Pattern mismatch
```

配列パターンにタプルをマッチさせようとしてもやはり失敗します。

```py
    print("Destructuring bind:")

    toil.walk(r""" tuple(a, b) := tuple(2, 3); print(a, b) """) # -> 2 3
    # toil.walk(r""" tuple(a, b) := 2 """) # -> Pattern mismatch

    toil.walk(r""" tuple(a, *b) := tuple(2, 3, 4); print(a, b) """) # -> 2 (3, 4)
```

分割代入です。書き方が長たらしくてすみません。

配列パターンの処理を流用してタプルをマッチさせているので、rest パターンも使えます。タプルの場合、通常はいくつの要素が含まれているか決まっているはずなので必ずしも rest パターンが必要とは言えないのですがあればあったで困ることもありません。

`tuple(a, *b) := tuple(2, 3, 4)` でタプルから rest パターンを使って残りを取り出すとタプル `(3, 4)` が取り出されています。それが何か？と思うかもしれませんがここも Python との相違点です。Python では配列として取り出されます[^why-different-type]。

[^why-different-type]: Python の分割代入（アンパック代入）は右辺にジェネレータなども含めさまざまなデータ型を取ることができ、rest パターンで取り出すとき統一的にどのデータ型でも元の型で返すことはできず、ならばということで「統一的に」配列で返すことにしたということのようです。詳しくは [PEP 3132](https://peps.python.org/pep-3132/) をご参照ください。Toil では配列は配列、タプルはタプルにマッチさせるので元の型で返すことについては問題ありません。もし Toil がジェネレータをサポートしていたら悩ましい判断になりそうです。ジェネレータを一度配列に変換してからマッチさせるのは確かに悔しい・・・

```py
>>> (a, *b) = (2, 3, 4)
>>> b
[3, 4]
```

Toil の内部では rest パターンで残りの要素を取り出す際、`value[i:]` を使っています。スライスの場合は元がタプルならタプルで取り出されるので実行例のような結果になっています。

```py
    print("Destructuring bind (for):")

    print(toil.walk(r"""
        a := [];
        for tuple(i, j) in [tuple(2, 3), tuple(4, 5)] do a.push([i, j]) then a end
    """)) # -> [[2, 3], [4, 5]]
    # toil.walk(r""" for tuple(i, j) in [2, 3] do None end """) # -> Pattern mismatch
```

for 式でも動きます。

```py
    print("Match:")

    print(toil.walk(r"""
        match tuple(2, 3) case tuple(a, b) then a * b case _ then 'no' end
    """)) # -> 6
    print(toil.walk(r""" [a, b] """)) # -> [2, 3]
    print(toil.walk(r"""
        match tuple(4, 5) case tuple(a, [b, c]) then a * b case _ then 'no' end
    """)) # -> no
    print(toil.walk(r""" [a, b, _] """)) # -> [4, 3, (4, 5)]
    print(toil.walk(r""" match 2 case tuple(a, b) then a * b end """)) # -> None
```

match 式も大丈夫。

あと、ここだけ取り出しても動かないので実行例としては挙げませんが、二分探索木を歩いて回る `bst_walk()` はこれまでこのように書いていました。

```
def bst_walk(bst) do
    if bst == None then None
    else
        bst_walk(bst[1]); print(bst[0]); bst_walk(bst[2])
    end
end
```

タプルにマッチできるようになったので以下の通りとてもすっきり書けます。`bst_put()` や `bst_find()` も同様です。

```
def bst_walk(bst) do
    match bst
        case None then None
        case tuple(val, left, right) then
            bst_walk(left); print(val); bst_walk(right)
    end
end
```

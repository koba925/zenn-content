title: "5.5 メソッド記法"
---

`keys(d)` は `d.keys()` と書けるようになりましたが、これはメソッドのように見えて中身はメソッドではありませんでした。Toil の `d.keys()` の呼び出しと Python の `d.keys()` の呼び出しとの違いは何でしょうか。Toil の `d.keys()` では `keys` がグローバルに定義された関数であるのに対し、Python の `d.keys()` では `d` が `keys` を持っているという点が違います。

ここに着目して、ドットにさらにメソッド風の呼び出し機能を追加してみましょう。`d := {keys: func ... end}` のような形を想定して、`d.keys()` という呼び出しを見つけたら `d.keys` の 1 つめの引数に `d` を渡してやればいいわけです。

・・・でもそれだと 5.3 節の `util.double(3)` のようなモジュール風の呼び出しの動きと矛盾してしまいますね？`double` の 1 つめの引数に `util` を渡されては困ります。

そこで、Toil のメソッド呼び出しでは、関数の最初の仮引数が `self` と指定されていることを条件とします。つまり `d := {keys: func self do ... end}` と定義されていれば `d.keys()` という呼び出しはメソッド呼び出しで、`d.keys` の最初の引数に `d` を渡すということにします。

こういうちょこまかとした場合分けが必要なのがやはり 1 つの記号に複数の意味を持たせているせいでしょう。やりすぎると破綻しそうです。まだギリギリ成立している気はしていますが・・・

実装は、やはり `Evaluator` に上記の考え方を実装するだけです。ここでも 1 つめの引数を関数とセットにして渡す `binding` を使います。

```diff py
 class Evaluator:
     ...

     def _dot(self, target_expr, attr_name, env):
         target_val = self.eval(target_expr, env)
         match target_val:
             case dict() if attr_name in target_val:
-                return target_val[attr_name]
+                match target_val[attr_name]:
+                    case (Ident("closure"), [[Ident("self"), *_], *_]) as func_val:
+                        return (Ident("binding"), [func_val, target_val])
+                    case attr_val:
+                        return attr_val
             case _:
                 func_val = env.val(Ident(attr_name))
                 return (Ident("binding"), [func_val, target_val])
```

ドットの左辺が辞書で、右辺に書かれたキーが存在したケースで、さらにそのキーに対応する値がどういう形かを見ます。`(closure, [[self, ...], ...])` という形、すなわち 1 つめの引数が `self` であるクロージャであればメソッドと見て、`binding` を返します。クロージャはこんな形をしていたこと、さらに `params` は仮引数の配列だったことを思い出して、この `case (Ident("closure")...` と見比べてください。`*_` は配列の残りの要素は無視するという意味になります。

```py
            case (Ident("func"), [params, body_expr]):
                return (Ident("closure"), [params, body_expr, env]) # ココ
```

そういう形でなければ普通に辞書の値を返します。

`binding` の使い方は同じなので `_op()` はそのままで大丈夫です。

実行例です。ドットの使い方をおさらいしながら進めましょう。

```py
    # Example

    print("Method notation:")

    print(toil.walk(r""" {add: 2}.add """)) # -> 2
```

ドットの左辺が辞書で、ドットの右辺に対応するキーがありますので、キーに対応する値を返します。


```py
    print(toil.walk(r""" 2.add(3) """)) # -> 5
```

ドットの左辺が辞書でないか、辞書であっても右辺に対応するキーがなければ UFCS です。右辺の関数の最初の引数として左辺の値を渡します。この場合は `add(2, 3)` を実行したのと同じことになります。

```py
    print(toil.walk(r""" {add: func a, b do a + b end}.add(2, 3) """)) # -> 5
```

ドットの左辺が辞書で、ドットの右辺に対応するキーがありますので、最初の例と同じくキーに対応する辞書の値を返します。その値が `func a, b do a + b end` なので、`a` に `2`、`b` に `3` を入れて `a + b` を計算します。モジュール風の呼び出しです。

```py
    print(toil.walk(r""" {a: 2, add: func self, b do self.a + b end}.add(3) """)) # -> 5
```

これが今回追加したメソッド記法です。
ドットの左辺が辞書で、ドットの右辺に対応するキーがあり、しかもその値が関数で、最初の引数が `self` なのでメソッドと見なされ、引数の並びの先頭にドットの左辺の値を追加して関数を呼び出します。この場合だとこのように展開・評価されている感じです。

```
   {a: 2, add: func self, b do self.a + b end}.add(3)
-> (func self, b do self.a + b end)({a: 2, add: func ... end}, 3)
-> {a: 2, add: func ... end}.a + 3
-> 2 + 3
-> 5
```

以下はメソッド記法がメソッドっぽく動いてる実行例です。よく出てくる動物クラス（のようなもの）を作ってみました。

```py
    print("Poor man's object:")

    toil.walk(r"""
        def Animal(name) do
            self := {};
            self._name = name;
            self.introduce = func self do print("I am", self._name) end;
            self.make_sound = func self do print("crying") end;
            self.rename = func self, name do self._name = name end;
            self
        end
    """)
```

ここではコンストラクタ（みたいなもの）に相当する関数を定義しています。

`self` という空の辞書を作り、属性として `_name` を、メソッドとして `introduce`・`make_sound`・`rename` を追加して最後に `self` を返します。メソッドの中で `self` を参照したり `self` の要素を更新していたりするところも見ておいてください。

```py
    toil.walk(r"""
        animal1 := Animal("Rocky");
        animal2 := Animal("Lucy");
        animal1.introduce();
        animal1.make_sound();
        animal2.introduce();
        animal2.make_sound();
        animal2.rename("Betty");
        animal2.introduce()
    """) # -> I am Rocky\ncrying\nI am Lucy\ncrying\nI am Betty
```

見た目は普通にオブジェクト指向っぽい書き方になりました。`introduce()` では `self` の要素の参照、`rename()` では `self` の要素の更新ができています。

なんと！継承（っぽいこと）もできます。

```py
    toil.walk(r"""
        def Dog(name) do
            self := Animal(name);
            self.make_sound = func self do print("woof") end;
            self
        end
    """)
```

サブクラス（らしきもの）を作るには、まず親クラスを作って `self` の初期値とします。`Dog` クラスなので鳴き声が `"woof"` になるよう `make_sound` を上書きしています。

```py
    toil.walk(r"""
        dog1 := Dog("Leo");
        dog1.introduce();
        dog1.make_sound()
    """) # -> I am Leo\nwoof
```

`_name` や `introduce` は継承されていますし `make_sound` はオーバーライドされました。なお `_name` は単なる辞書の要素なので隠ぺいはされていません。Python と同じです。

さて「のような」とか「ぽい」とか言ってますが実は JavaScript の「オブジェクト指向」も（もうすこし（かなり）手が込んでいますが）根っこのアイデアはこんな感じです。JavaScript の `class` 構文なんて飾りです。偉い人にはそれが（以下略

ところで、ここでもやはり `binding` を取り出しておき、後で呼び出すことが可能です。

```py
    toil.walk(r""" di := dog1.introduce; di() """) # -> I am Leo
```

Python でもカッコをつけずに `dog1.introduce` のように参照すると、インスタンス（`self`）が束縛された bound method という関数オブジェクトになり、変数に代入したり引数として渡したりできます。

```py
>>> a = [2, 3, 4]
>>> aa = a.append # bound method
>>> aa
<built-in method append of list object at 0x70fb688c9a40>
>>> aa(5)
>>> a
[2, 3, 4, 5]
```

実は `self._binary_left(..., self._and_or)` の `self._and_or` なども bound method でもうすでに多数お世話になっているのでした。

`binding` にはもう 1 つ面白い使い方があります。もとの関数の先頭の引数に値を割り当てて、ひとつ引数の減った関数として使うというものです。`map` は 1 引数の関数を引数にとりますので `add` を渡すことはできませんが、`10.add` とすることで `func b do 10 + b end` と同じことをする関数になるので渡すことができます。 

```py
    print(toil.walk(r""" [2, 3, 4].map(10.add) """)) # -> [12, 13, 14]
```

これは bound method というよりも部分適用（Partial application）と言った方がよいでしょう。Bound method を導入した目的からするとちょっと横道ですが紹介だけ。

ところで以下の `case _` について。

```py
    def bind(self, pattern: Expr, value: Value) -> bool:
        match pattern:
            case Ident() as ident:
                self.define(ident, value)
                return True
            case list():
                return isinstance(value, list) and self._bind_list(pattern, value)
            case _:
                return False
```

match 式も含めて考えると、変数でも配列でもなければエラー、はちょっと厳しすぎます。

```py
>>> a = 2
>>> match a:
...     case 1: 10
...     case 2: 20
... 
20
```

という使い方もありますので。このように、case 節に定数が来るパターンを Python ではリテラルパターンと言い、Toil もそれにならいます。定数パターンと呼ばないのは、Python にも Toil にも `const PI = 3.14` のように「定数」を定義する機能がないからです。慣用的には `MAX = 100` などとして定数として使うことはありますがこれはただの変数で、Python や Toil で `case MAX` と書くとこれは何にでもマッチするパターンになってしまいます。また、意味的には定数でも `case 2 * 3` のように計算式を書くこともできません。そういった混乱を避けるためにリテラルパターンと呼びます。

というわけで！

パターンと値の型が同じで `==` ならば OK ということにしてあげます。

`==` の判定だけにしないのは例の `1 == True` のようなケース [^true-false-value] で想定外の動作を防ぐためです。

[^true-false-value]: 1.5 節の「コラム：True と False の値」を参照。

1 行しか修正してませんけど！

```py
    # Example

    print("Literal pattern:")

    print(toil.ast(r""" match 2 case "2" then 20 case 2 then 200 end """))
    # -> (match, [2, [('2', 20), (2, 200)]])
    print(toil.walk(r""" match 2 case "2" then 20 case 2 then 200 end """)) # -> 200
    print(toil.walk(r""" match "2" case "2" then 20 case 2 then 200 end """)) # -> 20
    print(toil.walk(r""" match [2] case "2" then 20 case 2 then 200 end """)) # -> None
```

できました！

`2` と `"2"` と `[2]` がちゃんと別物として扱われてることも確認できました。

```py
    print(toil.walk(r""" match True case 1 then "int" case True then "bool" end """))
    # -> bool
```

`True` は `1` とマッチしませんね。念のため。

```py
    print(toil.walk(r""" [a, 2] := [3, 2]; a """)) # -> 3
    # print(toil.walk(r""" [a, 2] := [3, [2]]; a """)) # -> Pattern mismatch

    toil.walk(r""" def foo(a, 2) do a + 1 end """)
    print(toil.walk(r""" foo(3, 2) """)) # -> 4
    # print(toil.walk(r""" foo(3, 4) """)) # -> Pattern mismatch
```

使い道があるかどうかはわかりませんが分割代入や関数呼び出しでもリテラルパターンがそれなりにちゃんと働いています。

```py
    print(toil.walk(r""" 2 := 2 """)) # -> 2
```

これがエラーにならないのもご愛敬。

```py
    toil.walk(r"""
        def factorial_rec(n) do
            # if n == 0 then 1 else n * factorial_rec(n - 1) end
            match n
                case 0 then 1
                case _ then n * factorial_rec(n - 1)
            end
        end
    """)
    print(toil.walk(r""" factorial_rec(0) """)) # -> 1
    print(toil.walk(r""" factorial_rec(1) """)) # -> 1
    print(toil.walk(r""" factorial_rec(4) """)) # -> 24

    toil.walk(r"""
        def fib_rec(n) do
            # if n == 0 then return(0) end;
            # if n == 1 then return(1) end;
            # fib_rec(n - 1) + fib_rec(n - 2)
            match n
                case 0 then 0
                case 1 then 1
                case _ then fib_rec(n - 1) + fib_rec(n - 2)
            end
        end
    """)
    print(toil.walk(r""" fib_rec(0) """)) # -> 0
    print(toil.walk(r""" fib_rec(1) """)) # -> 1
    print(toil.walk(r""" fib_rec(6) """)) # -> 8
```

これは無理に match 式で書き換える必要はないんですけれどもこうも書けるということで。

小さい修正の節が続きますが 1 行の修正っていうのは究極ですね。でも match 式の表現力は大きく上がりました。すばらしい。

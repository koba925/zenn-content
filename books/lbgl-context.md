## 2. 書籍の基本方針とターゲット読者
* **ターゲット**: Python の基礎（リスト、辞書、クラス）は知っているが、言語処理系は初めての読者。
* **基本方針**: 厳密さよりも「楽しさ」「わかりやすさ」を優先。一度に多くの概念を詰め込まず、スモールステップで動かして達成感を持たせる。
* **トーン＆マナー**:
  * 親しみやすい語り口（読者への語りかけやユーモア）を維持する。
  * 各部・各章・各節の終わりには、次へのモチベーションを高める「ヒキ」を必ず入れる。
  * 専門用語は標準的なものを用いつつ、発展的な学習への橋渡しとなる注釈やコラムを適宜挟む。

## 4. Toil 言語の仕様・アーキテクチャ上の割り切り
* **Python ネイティブへの依存**: 数値・真偽値など、Python の値をそのまま Toil の値として流用。
* **AST 上の工夫（`Ident` クラス）**: 変数名と文字列データの混同を防ぐため、専用の `Ident` クラスを使用。
* **コレクションの AST 表現と構文糖衣**:
  * タプル: AST の式タグ自体に Python のタプルを使っているため、Toil のタプルは関数呼び出し形式の AST（`("tuple", [...])`）として扱う。
  * 配列: AST の式タグに使われていないため、AST 上でも Python の `list` をそのままリテラル表現として流用。
  * 文字列: raw 文字列およびエスケープ付き文字列ともに Python の `str` として評価。
  * 要素アクセス: `t[2]` は構文解析時に組み込み関数 `index(t, 2)` の呼び出しに変換（デシュガー）。
  * 関数定義: `def` も構文解析時に `define` と `func` にデシュガー。
* **割り切り（トレードオフ）**:
  * 「正しいソースコードが入力されれば正しく動くこと」を最優先とし、エラー処理・堅牢性・性能チューニングは深追いしない。
  * `break` / `continue` が関数を超えて大域脱出する挙動なども、実装をシンプルに保つための割り切りとして許容。

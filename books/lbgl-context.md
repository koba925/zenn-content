## 2. Toil の仕様・アーキテクチャ上の割り切り

* **値と AST の基本**: 数値・真偽値等は Python ネイティブ値を流用。変数名と文字列データの混同を防ぐため専用の `Ident` クラスを使用。
* **コレクション AST**: タプルは AST 式タグと衝突するため関数呼び出し形式 `("tuple", [...])`、配列は `list`、文字列（raw / エスケープ付き）は `str`、辞書は `dict`（キーは文字列のみ許容、識別子キーも文字列に正規化）を流用。
* **構文糖衣（デシュガー）**:
  * `def` → `define`＋`func`、`t[2]` → `index(t, 2)`、`defclass`/`defmethod` → `define`/`assign`/`dot`/`func`（引数先頭に `self` を埋め込み）。
  * アロー関数（`->`）→ `func`（`Evaluator` 変更なし、右結合、優先度は `:=`/`=` と `and`/`or` の間。非配列左辺は `[left]` に自動ラップ、配列 1 引数のみ外側 `[]` 必須）。
* **ドット記法（`.`）と `binding`**: (1) 辞書キー参照 → (2) キーなし時は UFCS → (3) キー値が第 1 引数 `self` の関数ならメソッド呼び出し。`(Ident("binding"), [func_val, target_val])` で bound method と部分適用を兼用。
* **パターンマッチ基盤（`Environment.bind()`）**: 成否を `bool` で返す設計に統一（関数呼び出し・分割代入・`for` 式は `assert` で `Pattern mismatch`、`match`・`try` 式は `False` で次節へ）。途中失敗の束縛も外側環境に残す割り切りと、`define` の上書き許容により `assign` を複雑化せず分割代入を実現。
* **各種パターン**: 配列とタプルは厳密区別（rest は `value[i:]` で元型維持）／リテラルは `type(p) is type(v) and p == v`（`1 == True` 誤マッチ防止）／辞書は値側の余剰キー無視／型は `type(v).__name__ == typ`（タプルは `tuple(*t)` 代替）／or は `|`（`or` は第 4 部で `if` 展開予定のため温存）。
* **モジュール（`load()`）**: `Environment(self._env)` の子環境で評価し、末尾の評価値（辞書）を返す Lua / CommonJS 風エクスポート。
* **例外処理（`try`/`except`/`raise`）**: 専用例外型は設けず任意の値を `ToilException` で送出しパターンマッチで振り分け。未捕捉は `Interpreter.eval()` で `Unhandled exception` アサート。
* **割り切り（トレードオフ）**: 「正しい入力が正しく動くこと」を最優先とし、エラー処理・堅牢性・性能チューニングは深追いしない。`break`/`continue` の関数越え大域脱出なども許容。

## 2. 書籍の基本方針とターゲット読者
* **ターゲット**: Python の基礎（リスト、辞書、クラス）は知っているが、言語処理系は初めての読者。
* **基本方針**: 厳密さよりも「楽しさ」「わかりやすさ」を優先。一度に多くの概念を詰め込まず、スモールステップで動かして達成感を持たせる。
* **トーン＆マナー**:
  * 親しみやすい語り口（読者への語りかけやユーモア）を維持する。
  * 各部・各章・各節の終わりには、次へのモチベーションを高める「ヒキ」を必ず入れる。
  * 専門用語は標準的なものを用いつつ、発展的な学習への橋渡しとなる注釈やコラムを適宜挟む。

## 4. Toil 言語の仕様・アーキテクチャ上の割り切り
* **Python ネイティブへの依存**: 数値・真偽値など、Python の値をそのまま Toil の値として流用。
* **AST 上の工夫（`Ident` クラス）**: 変数名と文字列データの混同を防ぐため、専用の `Ident` クラスを使用。
* **コレクションの AST 表現と構文糖衣**:
  * タプル: AST の式タグ自体に Python のタプルを使っているため、Toil のタプルは関数呼び出し形式の AST（`("tuple", [...])`）として扱う。
  * 配列: AST の式タグに使われていないため、AST 上でも Python の `list` をそのままリテラル表現として流用。
  * 文字列: raw 文字列およびエスケープ付き文字列ともに Python の `str` として評価。
  * 辞書: AST 上でも Python の `dict` をそのままリテラル表現として流用。キーは単純化のため文字列のみ許容（識別子キーも文字列に正規化）。
  * ドット記法（`.`）の多重化:
    1. 辞書の要素アクセス（キーが存在する場合）
    2. UFCS（辞書キーが存在しない場合、環境から関数を探して第 1 引数をバインド）
    3. メソッド呼び出し（辞書キーに関数があり、第 1 引数が `self` の場合に `binding` を生成）
  * バインディング値: `(Ident("binding"), [func_val, target_val])` は bound method と部分適用の両方の基盤として機能。
  * クラス構文: `defclass` / `defmethod` は専用の AST タグを持たず、構文解析時に既存の `define` / `assign` / `dot` / `func`（引数先頭に `self` を埋め込み）へと展開する構文糖衣。
  * 要素アクセス: `t[2]` は構文解析時に組み込み関数 `index(t, 2)` の呼び出しに変換（デシュガー）。
  * 関数定義: `def` も構文解析時に `define` と `func` にデシュガー。
* **パターンマッチと応用機能（第 6 章）**:
  * **共通基盤（`Environment.bind()`）**: マッチ成否を `bool` で返す設計に統一。関数呼び出し・分割代入・`for` 式では戻り値を `assert` して `Pattern mismatch` で停止、`match` 式・`try` 式では `False` 時に次の節へフォールバック。
  * **スコープと副作用の割り切り**: `match` 式や途中失敗したパターンで束縛された変数も外側の環境にそのまま残る（他構文とのスコープ一貫性・シンプルさ優先）。`define` が既存変数の上書きを許す仕様により、`assign` を複雑化せず分割代入を実現。
  * **各種パターンの仕様**:
    * 配列とタプルは厳密に区別（Python との相違点）。rest パターンはスライス `value[i:]` のため元の型（配列/タプル）で返る。
    * リテラルパターンは `type(pattern) is type(value) and pattern == value` で `1 == True` の誤マッチを防止。
    * 辞書パターンは値側の余剰キーを無視する緩い仕様（部分インポートにも活用）。
    * 型パターンは `type(value).__name__ == typ` で判定。タプルは `tuple(...)` と衝突するため対象外（`tuple(*t)` で代替）。
    * `or` パターンは `|` を使用（`or` は第 4 部で `if` に展開され AST から消える予定のため温存）。
  * **モジュール（`load()`）**: `Environment(self._env)` の子環境で評価し、末尾の評価値（辞書）を返す Lua / CommonJS 風のエクスポート方式。
  * **アロー関数（`->`）**: `Evaluator` 変更なしの構文糖衣（右結合、優先度は `:=`/`=` と `and`/`or` の間）。左辺が配列でなければ `[left]` に自動ラップ（1 個の配列を受け取る場合のみ外側 `[]` が必須）。
  * **例外処理（`try` / `except` / `raise`）**: 専用の例外型は設けず任意の値を `ToilException` で送出しパターンマッチで振り分け。未捕捉例外は `Interpreter.eval()` で `Unhandled exception` としてアサート。
* **割り切り（トレードオフ）**:
  * 「正しいソースコードが入力されれば正しく動くこと」を最優先とし、エラー処理・堅牢性・性能チューニングは深追いしない。
  * `break` / `continue` が関数を超えて大域脱出する挙動なども、実装をシンプルに保つための割り切りとして許容。
